    04Design notes
    Why these boundaries?
    Rationale below follows observable code structure and comments. Tradeoffs are consequences of the implementation, not promises of future behavior.
    

    One operation contract.
    Bindings store Requests. The palette, CLI, socket and MCP read the registry and schemas. ExecuteAt validates arguments, resolves instance targets, checks availability and policy, then runs the applicable noun action or operation handler.
    Runtime.ResolveTarget maps foreign record IDs into live instances; the resolver is shared by all entrances.
    runtime.go · ExecuteAt, TargetInstance
    

    Behavior follows ancestry.
    Nouns share behavior; instances supply local rows, parent links and components. Capture rows run outer-first, then ordinary rows bubble inner-first. Editor bindings are data in the same resolver, including counts and operator-pending modes.
    One Runtime.Mode governs interaction. Focus changes reset it to the destination's declared mode; modal Pop restores the return base mode.
    resolve.go · DispatchOutcome · focus.go · setFocus, Pop
    

    Keep local state with its owner.
    Page components remember focus/mode. Inputs retain text and undo trees while covered. Modal components own their own selection, input or scroll state; created modal subtrees are removed on Pop.
    Open modals block page navigation. Retained objects do not imply persistent data after restart or after their subtree is removed.
    pages.go · Page · instance.go · Instance.Component
    

    Work returns to the loop.
    Pending work captures immutable inputs. Ticket ownership, replacement slots and cancellation prevent stale completions from applying. Then runs on the loop only for a current ticket; removing the owner cancels its jobs.
    Components can use the delivery interface directly; the picker also checks its own index and search generations.
    delivery.go · Pending, Ticket, Deliver
    

    Schema drives the shared UI.
    Props and stores supply standard verbs, record editors, choices, row metadata and host catalogs. Lists, trees, timelines, forms, Settings/About and terminals retain typed state in components.
    Help and hints read bindings. Views report placements so visual focus order follows drawing order.
    props.go · PropSpec, Store · record_editor.go · RecordSpec
    

    Extend through declarations.
    User actions run declared external argv as jobs. Event hook rows call verbs. Catalog hosting mounts namespaced metadata and proxy handlers; MCP uses a backend over the same headless request path.
    Actor attribution is advisory identity, not authentication. Executable actions come only from the user's file; returned extension text is data.
    Extension guide · actor.go · Actor
    

    Current boundaries
      

    • Runtime is owned by one event loop. Workers return messages; they never mutate live components.
      • 

    • Socket transport is local Unix-domain IPC with a private owner directory and a mode-0600 socket. MCP is sequential stdio JSON-RPC; its headless backend does not attach to a live TUI.
      • 

    • Configuration can declare external-command actions and aliases. It does not hot-load arbitrary in-process Go code or render callbacks.
      • 

    • Macro replay runs through Runtime.Dispatch synchronously and does not wait for asynchronous indexing or jobs. Error cleanup does not roll back earlier text edits.
      • 

    • Watch fallback relists after known changes; it does not poll for arbitrary external writes. A store that needs outside notifications supplies Watch.
      • 

    • Cancellation rejects stale application results but cannot reverse external side effects already performed by a worker.
      • 

    • Input offsets are rune indices; layout uses terminal cells and grapheme-aware helpers. Render callbacks can update viewport caches and placements.
      • 

    • Catalogs describe supported components and operations. Extension guards remain enforced at the extension. Actor metadata is not an authentication mechanism.
      • 

    • This guide is an authored source snapshot. Source labels name declarations; generated catalogs and diagrams have separate regeneration workflows.
