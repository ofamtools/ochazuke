## v0.34.0 (2026-10-28)

### Default key bindings are embedded data

- The framework's default rows moved out of Go `Bind` chains into embedded files in the grouped format, the only place a default key is written: `bindings/*.json` (app, chooser, completion, confirm, detail, editor, focus, form, help, history, list, list-modes, macros, modal, palette, panes, picker, registers, settings-editor, table, terminal, timeline, tree, yank-history), `markdown/bindings.json`, `grid/bindings.json`, `cli/bindings.json`: 478 rows. `editor_bindings.json` and `registers_bindings.json` are gone, with their spec format (`maps`/`expand`, `pending`, `rows`); `Runtime.LoadBindingSpec` is removed (no consumer used it): use `LoadDefaultBindings`.
- New `Runtime.LoadDefaultBindings(source, data)`, `MustLoadDefaultBindings`, `LoadDefaultBindingsFS(fsys, patterns...)`: an application's embedded defaults go into the default layer, below the user's `bindings.json`, exactly where Go rows would. An error in an embedded file fails the load (unknown operation, argument, source, guard, mode, instance), unlike a user file's skipped rows.
- New `Runtime.CheckDefaultBindings(source, data)`, the rule check for tests: every name exists, `mode.enter` goes into a pending mode, no two rows of a table clash.
- New verb `ochazuke.bindings.defaults` (`BIN bindings defaults`) and `Runtime.DefaultBindings` (`DefaultBinding{Binding, Source}`): the default layer, the user's rows left out, each group tagged with its source (the embedded file, `go`, `generated`). New result type `Verbatim`, which the CLI prints as text.
- The grouped format gains two group fields: `"fallback": true` (keep the keys the table bound before the file loaded: the app noun's rows `NewModel` used to add only when the application had not bound the key) and `"source"` (written by `bindings defaults`, ignored on read). `BindingGroup.Fallback`, `BindingGroup.Source`.
- Rows from a file keep the types their operation declares (a whole number for an integer parameter is an `int`); `mode.enter`'s `request` is the decoded object, which it reads as before. The terminal leader setting moves the leader rows and keeps their source.
- Unchanged behaviour: every stored table of NewRuntime, NewModel (with picker, markdown, grid, the leader moved to ctrl+b), examples/full-project and all 313 o-story apps is row for row the same before and after; only the leader row's nested request prints its fields in sorted order.
- Tests `TestFrameworkBindingFilesPassTheRuleCheck`, `TestFrameworkBindingFilesDoNotClash`, `TestEveryFrameworkBindingFileIsLoaded`, `TestLoadDefaultBindingsFailsLoudly`, `TestLoadDefaultBindingsMatchesTheGoBuilder`, `TestBindingsDefaultsPrintsTheDefaultLayer`, `TestTerminalLeaderKeepsTheRowsSource`, `TestCommandBindingsPassTheRuleCheck`, `TestBindingsDefaultsPrintsAFile`, `TestGridBindingsPassTheRuleCheck`, `TestMarkdownBindingsPassTheRuleCheck`.
- Consumers: nothing breaks. An app moves its own defaults by embedding its files and calling `LoadDefaultBindingsFS` where its `Bind` calls were.

## v0.33.0 (2026-10-28)

### Bindings files are grouped by context; config files are JSONC

- Config files are JSONC: `bindings.json`, `actions.json`, `settings.json`, `themes.json`, `bindings load` and the embedded default specs accept `//` and `/* */` comments and trailing commas (`github.com/tailscale/hujson`, new dependency). Files keep their `.json` names; errors name the line and column of the file as written. Plain JSON without a `/` skips the parse (100 KB: 0.12 ms against 2.5 ms). New `StandardizeJSONC`, `DecodeJSONC`.
- `settings set` edits an existing `settings.json` in place through the hujson AST: the user's comments, layout and member order stay.
- New grouped bindings format: `{"modes": {...}, "bindings": [{"context": "noun/mode", "extends": "...", "bindings": {"key": "noun.verb" | {action, args, hint, when, ...} | null | [...]}}, {"instance": "ID", "mode": "MODE", "bindings": {...}}]}`. `config export`'s `bindings.reference.json`, the new verb `bindings export PATH [--force]` and the `cmd/ochazuke` keybinding tool write it (one header comment, groups by noun then mode, then instances, keys one per line in exact table order: a key that returns after other keys starts another group for the same context, an alias-spelled row is written as spelled). New `ParseBindings`, `FormatBindings`, `Runtime.BindingsDoc`, `GroupBindings`, `BindingsDoc`, `BindingGroup`, `ModeSpec`, `Config.BindingsFormat`, `BindingsGrouped`/`BindingsRows`/`BindingsHeader`.
- `bindings.json` and `bindings load` read the grouped format and the old array of rows (the top level tells them apart), so existing files keep working and nothing is rewritten. `bindings check` names the format read on the status line. A bad group or key is skipped and reported (`bindings.json: pane/normal q: ...`). A user file's `modes` or `extends` that differ from the application's are reported and ignored.
- `settings.reference.json` and `actions.example.json` are written one row per line (`FormatRows`, `FormatRowsJSON`). `bindings list --json` still answers an array of rows, now with `keys`/`pattern` before `request` (the `Binding` field order).
- The keybinding tool imports both its old `{keys, action}` array and the grouped file.
- Tests `TestFormatBindingsGolden`, `TestFormatBindingsRoundTrip`, `TestParseBindingsReadsTheRowsFormat`, `TestBindingsRowsToGroupedSameEffectiveRows`, `TestBindingsFileJSONC`, `TestBindingsFileMalformedPosition`, `TestBindingsCheckReportsFormat`, `TestBindingsFileModesMustAgree`, `TestBindingsFileBadKeySkipped`, `TestBindingsExportVerbLoadsBack`, `TestSettingsWriteKeepsComments`, `TestFormatRowsKeepsStructOrder`, `TestConfigExportWritesRowFiles`, `TestBindingExportGroupedFormat`; `TestBindingsExportRoundTripsEveryTable` (examples/full-project) and `TestBindingsExportRoundTripsEveryStoryApp` (every o-story app: exported, read back and loaded into a fresh build, the same ordered rows per table); benchmark `BenchmarkStandardizeJSONC`.
- Consumers (mtm, nabe, o-* tools) pick it up with the release; nothing to change. A user's `bindings.json` in rows format keeps loading.

## v0.32.0 (2026-10-28)

### The half-page rule: one motion press scrolls at most half a view (R3.14)

- A motion (`j`/`k`, a step inside a card, `}`/`{` in a Markdown document) whose target would scroll the view more than half its height scrolls half toward it, and the cursor moves only once the target shows. Page keys (`ctrl+d`/`ctrl+u`, `pgdown`/`pgup`, `J`/`K`), `G`/`gg` and searches keep their sizes. One helper: `MotionScroll(want, page)` and `SpanInView(from, to, page)` (motion_scroll.go).
- Card timelines, measured in a 15-line window over cards of 5, 30, 12, 40 and 3 lines: card-to-card `j` scrolled 9, 34, 16 and 36 lines per press, now 7 at most; step-to-step `j` scrolled up to 15 and 16 lines (16 onto the next card), now 7 at most. A tall card or step is read half a window per press (`List` routes `list.move` to a component's own motion; the timeline's `cardMotion`).
- Card timelines reach their end before leaving: `j` on the last card, or on its last step, scrolls until the card's end shows, then spills (R3.4) or, `NoSpill`, stays with the focus where it was. Before, `j` on the last step of a tall last card spilled with the card's end still off screen. `k` on the first card scrolls to its top first.
- `markdown.Doc`: `}`/`{` through a block taller than the window page half a window per press, the line cursor held inside the window until the next block shows. `]]`/`[[` and `] KIND` stay jumps.
- Stories `timeline/card-half-page`, `timeline/card-end-clamp`, `timeline/step-end-clamp`, `timeline/card-top-clamp`, `timeline/spill-after-end`, `markdown/motion-long-block` (new), `timeline/step-tall` (now exactly half a window per press); tests `TestTimelineHalfPageRule`, `TestTimelineNoSpillScrollsToTheEnd`.

### `h` inside a card folds the open section

- Inside a card, `h` (and `left`) on a step in an open foldable section (a titled step with a body: a tool call, thinking, an answer, any of its paragraphs) folds it and puts the cursor on its title: new verb `timeline.fold-step`, guarded row `timeline-step-open` before the unguarded `timeline.leave`. On a folded or plain step `h` goes back to the card as before; `l` on a folded step opens it as before. The footer inside an open section reads `h timeline.fold-step`.
- Story `timeline/step-fold` (new), goldens `timeline/step-marker-{dark,mono}-80` (footer); test `TestTimelineHFoldsAnOpenStep`; UX-RULES R13.1's table.
- Consumers: mtm (Turns) and any app with a card timeline get both with the release; an app that wants `j` never to leave its timeline marks it `NoSpill()`.

## v0.31.0 (2026-10-28)

### A noun's row source prefers its own rows

- `cli.CatalogDoc.RowSource` took the first verb (sorted) declaring rows, so `slack-channel.history` (rows of `slack-message`) beat `list` as the channel noun's row source. The rule is now, each step in sorted order: `list` when it declares the noun's own rows; another verb declaring the noun's own rows; a `list` declaring none (the noun's own rows); a verb declaring another noun's rows. A catalog page's list with no `source`, `ListColumns` and the hosts' mounts (mtm, nabe) follow it.
- Checked against every installed tool's catalog (`BIN catalog`: mtm, nabe, o-ai, o-animation, o-csv, o-dotfiles, o-gh, o-git, o-inventory, o-json, o-mcp, o-md, o-proj, o-qbt, o-tui, and o-slack from source): every row source is the same except the ones the bug picked: `o-gh` `pr` (`ignored` → `list`), `o-mcp` `mcp-server` and `mcp-tool` (`calls`, rows of `mcp-call` → `list`), `o-slack` `slack-message` (`dms` → `list`) and, with its workaround removed, `slack-channel` (`history` → `list`).
- No explicit row-source declaration on the noun: no catalog needs one the rule does not give.
- Tests `TestCatalogRowSourcePrefersTheNounsOwnRows`; story `catalog/row-source-prefers-list` (new).
- Consumers: o-slack can declare `.Rows(messageNoun)` on `slack-channel.history` again once it takes this release.

### The status line: an error tone and a plain tone

- `Ctx.Status` was drawn as `Error: …` in the error style while the docs called it a plain status line, and the CLI printed it as `status:`. The status line is now one slot with two tones: `ctx.Error(text)` (an error: `Error: TEXT` in the error style in place of the hints) and `ctx.Info(text)` (a plain message, before the hints cut to half the width); either replaces the other and the next key clears both. `ctx.Status` keeps its meaning as the error tone (the older spelling of `Error`), so every existing caller that reports a failure stays an error. `Notify` stays the notice that persists. Same on `r.UI()` (`Error`, `Info`, `Status`).
- Sinks: `UISink` is unchanged (`Status` is the error tone); a sink that also implements the new `InfoSink` (`Info(text)`) shows the plain tone, one without it gets it through `Status` (as before). `Model.Info` is the plain tone beside `Model.Status`. `UIInfo` (`"info"`) is a new `UIMessage` kind; `UIStatus` keeps `"status"` on the wire. `UIMessage.Line`. `RecordingSink.Info`, `LastInfo` (`LastStatus` is the error tone).
- CLI: `cli.Shell` and `ochazuke NOUN VERB` print the error tone as `error: TEXT` (was `status: TEXT`) and the plain tone as `status: TEXT`.
- Framework callers: `list.yank`'s "copied the row (N characters)" is `Info` now (it read `Error: copied …`); `markdown` writes `Error`.
- Rules: R6.4 (rewritten). Stories `chrome/status-info-plain-80`, `chrome/status-error-clears-80`, goldens `chrome/status-info-80`, `chrome/status-error-80` (new); tests `TestStatusLineTones`, `TestStatusInfoReachesEverySink`, `TestShellPrintsNoticesAndStatusOnStderr` (extended).
- Consumers (nothing breaks; plain messages read `Error:` until moved): move plain messages to `ctx.Info`: o-csv (`wrote … rows`, `rows N–M of T`, `copied …` x2), o-json (`copied …` x2), o-git (`changed`'s `say`), o-md (`sent N notes`), mtm (`queued …` x2 in prompt_box, `attached …` in prompt_attach). mtm's `noticeSink` forwards `Info` (implement `InfoSink`), or the plain tone still reads `Error:` there. Every `err.Error()` caller can stay on `Status` or be renamed `Error`.

### Focus never rests on what the last frame did not draw

- After the Model draws the current page, a focus whose stop that frame did not place (a tab switched away from it, a collapsed panel) moves to its nearest ancestor below the page that was drawn (a list nested under a row: the row), else to the page's first stop in drawing order (its remembered child), else to the page; the page is drawn again before the footer, so the hints and the next key are what is on screen (`Runtime.keepFocusShown`, `Model.render`). A list row counts as drawn when its list is, a grid cell when its grid is, a card's body when its timeline is. It is a plain focus change: the mode rule applies (a hidden prompt in insert leaves to normal) and the stop left remembers its child, so `}` goes back once it is drawn again. It waits while a modal is open, before the page's first frame (the CLI), after a frame that placed no stop, and never judges a focus on no stop (the page, a panel).
- Rules: `docs/UX-RULES.md` R3.13 (new). Stories `focus/hidden-stop-moves-focus`, `focus/hidden-input-leaves-insert`, `focus/hidden-timeline-card` (new); tests `TestFocusHidden*`. o-story: `demo.hide {id}` stops drawing a list, tree, input or the timeline, or draws it again.
- Consumers: an app that moved the focus off a panel it stopped drawing (mtm's `leaveHiddenTurns`) can drop that code. An app whose own focusable view never calls `Runtime.Placed` while other stops on the page do now loses the focus off it after a frame (jumps already skipped such a stop); call `Placed(id)` from the view.

## v0.30.0 (2026-10-28)

### Timeline: step inside a card

- Inside a card is a focus place, not a mode (`timeline_steps.go`). `l` on a closed card opens it (as before); `l` on an open card steps inside onto its first step, the focus on the timeline's body instance (`<id>/body`, noun `ochazuke.timeline-body`, under the card list); `h` inside goes back to the card (still open), `h` on an open card closes it, `h` on a closed card goes to the timeline's parent stop (`ParentStop(id)` option, `Timeline.SetParentStop`; without one it stays). `enter`/`space` still toggle; closing the card from inside puts the focus on the card.
- Inside: `j`/`k` move by step (counts work, a count stops at the edge); a step taller than the window moves half a window per key first; past the last step `j` spills to the next card (open or closed), past the last card to the next stop; past the first step `k` goes back to the card; `l` opens the step's folded section; `y` yanks the step's text through the registers; `esc` leaves like `h`. The current step is marked `▌` (accent, bold) in the left padding of its lines, never reversed; the window scrolls to keep it shown.
- API: `Card.Steps []CardStep{ID, Title, Summary, Role, Folded, Header, Paragraphs, Body}` (a `Header` step is the card's header; a titled step with a body folds like a section and counts in `z N` and `timeline.fold`; `Paragraphs` splits a body into a step per paragraph). Without Steps a card steps through its Body's paragraphs (blank-line separated, a fenced code block one paragraph) and then each section as one step, and draws exactly as before. `TimelineBodyNoun`, `Timeline.InBody`, `Step`, `StepText`, `BodyID`.
- Verbs on `ochazuke.timeline`: `enter {card}`, `leave`, `step {delta, count}` (a motion), `yank-step {register}`; `open`, `close`, `toggle` stay. Guards `timeline-card-closed`, `timeline-card-open`, `timeline-in-body`. The `l`/`right` and `h`/`left` rows on `ochazuke.timeline` are now guarded by place (closed: open and leave; open: enter and close), so `?` help and the footer show the row that answers. Body rows on `ochazuke.timeline-body`: `j`/`down`/`k`/`up` step, `l`/`right` enter, `h`/`left`/`esc` leave, `y` yank-step.
- `List` gains an unexported part (an instance that holds the list's focus as a row does); `List.syncFocus` keeps it while the selected row stays. o-story: `CardSpec.Steps` (`StepSpec`) and `Expect.Register` (the unnamed register's text).
- Rules: `docs/UX-RULES.md` R13 (new). Stories `timeline/step-in`, `step-out`, `step-spill`, `step-back`, `step-tall`, `step-yank`, `step-explicit`, `step-enter-toggles`, `step-marker-{dark,mono}-80` (goldens). Goldens `timeline/open-close-120` and `follow-tail-120` updated (the footer reads `l timeline.enter` on an open card).
- Consumers: an app that binds its own `l` on its card noun (mtm's `turn.open`) shadows `timeline.enter`; bind `l` to `ochazuke.timeline.enter` guarded `timeline-card-open` on that noun to step in. Existing `Card` users compile unchanged.

## v0.29.0 (2026-10-28)

### Help: whole sequences, a row for every prefix, a pending mode's keys

- `?` help's key column is the whole sequence (`ctrl+a v`, `g c x`); the v0.27.0 prefix | key split is gone (R6.9 keeps its order, R6.10 is new).
- Every prefix has a row of its own, read the same whatever makes it one: a row entering a pending mode (`ctrl+a` → `leader_pending`: `mode.enter`, "enters leader_pending: waits for the next key (N keys)", and what it does alone after the timeout), or the first key of sequences with nothing bound on it alone (a made row, no operation, "waits for the next key (N keys)"). A prefix bound to an operation of its own keeps it. Under the prefix's row come its sequences, each once, a longer prefix's row under the one it extends.
- A pending mode's rows are listed under the key that enters it as whole sequences: over a live terminal `?` shows `ctrl+a`, then `ctrl+a d`, `ctrl+a ctrl+a` and every app row bound in `leader_pending`, following the `terminal-leader` setting. Hidden rows of the mode (the leader's `any` and `paste`) stay out; a mode row that enters a mode expands once more, then shows `mode.enter`. Rows with their own `Help` (registers, macros, counts) and operators stay one row.
- `HelpRow` gains `Group` (a prefix row), `Under` (the prefix row it is listed under), `Enters` (the pending mode the row's key enters) and `Steps []HelpStep{Key, Operation, Mode, Description}` (a sequence key by key). Additive (`omitempty`). `BindingHelp` and `PlaceHelp` return the made prefix rows and the mode rows; `Key` is the whole sequence as before.
- The help (here and pick) is a tree (R11.1): a prefix row holds its sequences and starts open; a sequence row holds its steps, one key per line (`ctrl+a` "enters leader_pending: waits for the next key", then `v` and what it runs), and starts closed. `l`/`h` (and the arrows) open and close, `enter` toggles (a hidden row on the `binding` noun, guard `help-tree`, so the footer is unchanged), `j`/`k` move across everything shown, `z l`/`z h` scroll the columns. The filter reads a row with its steps and its sequences. The table view stays a plain table (h/l scroll its modes). The help's tree is `__bindings-help` and its list keeps the id `__bindings-help/list`. `TreeNode` gains `Section` (a label line above a run of rows, as `ListItem.Section`).
- o-story: a page takes `pending` (pending modes defined before its `bind` rows).
- Rules: R6.9 (reworded), R6.10 (new). Stories `help/leader-sequences`, `help/leader-rebound`, `help/mode-cycle`, `help/sequence-steps`, `help/filter-finds-steps` (new), `help/prefix-columns-{80,120}` (rewritten), `tables/modal-clamps` (now on the help's table view, whose h/l still scroll). Goldens regenerated for the one-column key and the prefix rows: `testdata/help-80.golden` (`d` reads "waits for the next key (2 keys)" above `d d` and `d esc`; the list's `g esc` moves under movement beside `g g`), `help/pick-place.golden`, `help/prefix-columns-{80,120}.golden`, `tables/modal-clamps.golden` (the table view), `help/pick-view.golden` (the tree's fold markers).
- Consumers pick it up on the next tag. mtm: `?` over a live pane lists the leader and every leader key with its description; its `terminal.keys` modal stays.

## v0.28.0 (2026-10-28)

### Actions: a flat table with aliases

- The action table is flat: a key is a name looked up whole, and the action carries its own noun and verb, so a verb may hold a dot again (`dirs.base.add` is the verb `base.add` of `dirs`). `Register` no longer panics on a dotted verb; two declarations that spell the same name (`tool` + `part.run` beside `tool.part` + `run`) are still a duplicate. `CanonicalKey` looks a name up whole before reading its dots, `Runtime.Operation`, `VerbGuard` and `NounBuilder.When` read a registered key's parts from its action. This is what fixes nabe's startup panic (`verb "base.add" of mtm-dirs holds a dot`) on a registry holding mtm's old catalog, with no nabe change.
- Action aliases (`action_names.go`): `ActionAlias{Alias, Action, Noun, Verb, Since, RemoveAfter, Note, Source}`; `Runtime.AddActionAlias`, `AliasAction`; `NounBuilder.Alias(verbs...)` (same noun, permanent), `AliasOn(noun, verb)` (one operation under both nouns' names: `project.associate` for `pane.associate`), `Renamed(old, since, removeAfter)` (a deprecated old name); lookups `ResolveAction`, `ActionAlias`, `ActionAliases`, `AliasesOf`, `ActionAliasProblems`, exported `CanonicalRequest`. An alias may not take the name of an action or of another alias; an action registered after an alias of its name takes the name and the drop is recorded, never a panic.
- Running through an alias runs the canonical action: `Request.Via` (new, `omitempty`) keeps the alias a request was spelled by (history shows it); the handler reads `Ctx.Invoked` (new field) or `Runtime.Invoked()`: `Invocation{Name, Noun, Verb, Alias}`, `Noun` being the alias's noun (the subject side). A deprecated alias's first use in a runtime posts one notice: `OLD is an old name of NEW (renamed in SINCE; removed after AFTER)`.

## v0.25.0 (2026-10-28)

### Tables: h/l scroll, then move the focus; edge markers; pinned columns

- Scroll, then move the focus: the horizontal twin of the `j`/`k` spill. On a row-select table `l` scrolls the view one column right (`list.scroll-columns {delta: 1}`, counts work) until the last column shows, then moves the focus to the next stop (`focus.next`); `h` scrolls left until offset 0, then moves it to the previous stop (`focus.previous`). On a cell-mode table `h` on the first column and `l` on the last move the focus; in between they move the column as before. The arrows do the same. A count never spills (it stops at the edge, as `3j` stops at the last row). In a modal, on a `NoSpill` list and at the page's first or last stop the keys clamp. A row noun's own `h`/`l` (a setting's cycle, an app's open) still answers first. (This release also said a tree's expand and collapse still answer first; they did not on a tree with columns, whose list answered before the tree: see the fix under Unreleased.) Every table, cell-mode or not, takes part: a table that fits is at both edges, so `l` on it moves the focus where nothing inner binds `l` (it did nothing before).
- Done with guarded rows, no new verb: per key, rows of `list.column` (guard `table-column-right`/`-left`), `list.scroll-columns` (`table-scrolls-right`/`-left`), `focus.next`/`focus.previous` (`table-spills-right`/`-left`), then the clamped `list.column` (`table-cells`) and `list.scroll-columns` (`table-scrolls`); the first whose guard holds answers. `table-scrolls` is kept for `z l`/`z h`.
- Edge markers: a table with a header that hides a column reserves 8 cells (two markers and their gaps; more with ten or more scrolling columns) and draws `‹N` after its pinned columns (N scrolling columns hidden before the view) and `N›` at its right edge (hidden after it), each only when N > 0, so the user sees whether `h`/`l` will scroll or move on. A table that fits reserves nothing. A table without a header draws none.
- Pinned columns: any columns can be pinned; they draw first, in declared order, and never scroll. The default is the columns declared `Column.Pinned` (`pinned` in a catalog's columns), else the first column, which is the old frozen first column. Verbs on the list noun (verb guard `list-table`): `pin-column {column}`, `unpin-column {column}`, `toggle-pin-column {column}` (`z p` on a cell-mode table, the current column) and `unpin-columns`; `column` is a title or a 1-based number in declaration order, and without it a row-select table opens the column chooser. `reset-columns` (`z =`) also puts the default pins back, and its verb now answers on any table (the palette resets a row-select table's pins; `z =` stays a cell-mode key). Pins are remembered per table id in `tables.json` (`TableState.Pins`; a row-select table now writes its pins too, nothing else). When the pins leave no room for a scrolling column the view drops pins from the right (the saved pins stay). On a cell-mode table `h`/`l`, `0`/`$` and `N|` move in drawing order (pins first).
- `z l` from the start skips an offset 1 that draws what offset 0 draws, and offset 1 equal to 0 is drawn as 0, so no key press scrolls without a visible change (`2 z l` from the start lands one column further than before).
- Go: `Column.Pinned`, `List.PinnedColumns`, `SetPinnedColumns`, `PinColumn`, `UnpinColumn`, `UnpinColumns`, `ResetPins`, `TableState.Pins`. Unscrolled layout: scrolling columns drop by `Priority` down to one before any pin, then pins from the right down to the first; a first column with a larger `Priority` than the others no longer drops before them.
- Resolution fixes found on the way: a key-sequence prefix waits only for sequences whose row guard holds too (`z` on a row-select table that fits still waits for nothing, with the cell-only `z =`/`z p` rows guarded), and a row whose own guard is false no longer shadows an outer row's hint on the same key (the timeline's `l timeline.open` hint is back beside the list rows).
- Rules: `docs/UX-RULES.md` R5.11 (scroll, then move the focus), R5.12 (edge markers), R5.13 (pins); R5.9 and R5.10 updated. Stories `tables/scroll-then-focus-{right,left}`, `tables/cell-edge-focus`, `tables/nospill-clamps`, `tables/modal-clamps`, `tables/row-noun-l-wins`, `tables/edge-markers{,-start,-fit}`, `tables/pin-{cell,row-palette,declared,narrow}`, `tables/unpin-columns`. ### Framework namespace `ochazuke`

The framework namespace is `ochazuke`, not `app`: v0.16.0's `app.<noun>` framework names collided with the app noun's own verbs (`app.state`, an application verb, against the framework noun `app.state`).

- Framework nouns are canonical `ochazuke.<noun>` (`ochazuke.settings`, `ochazuke.list`, `ochazuke.page`, `ochazuke.state`, `ochazuke.command`, `ochazuke.grid`, `ochazuke.markdown`, …); `FrameworkNamespace` is `"ochazuke"`, and the new `AppNoun` (`"app"`) is never namespaced. ### Card timelines

- New component `Timeline` (`timeline.go`): `Runtime.AddTimeline(id, cards, opts...)` draws a scrolling column of boxed cards of varying height (`Card`: header wrapped in full, a meta line, a body and foldable `CardSection`s shown only while open, each section in its own `CardRole` style). Cards are instances of the app's nouns (rows of a list child), so selection, j/k with counts and spills, `g g`, ctrl+d/ctrl+u and the `/` filter are the list's. Options `FollowTail()` (stick to the end: appends select the newest card, a growing last card keeps its end in view; moving or scrolling up stops it, `G` or reaching the end resumes), `HeaderLines(n)` (cap a closed header with `… N more lines`), `NoSpill()`.
- Emphasis: `Active` (bold header, `●` in the top border, readable in mono), `Muted` (older cards), `Group` (a labelled full-width rule between groups). Selection: the selected card's header reversed and its border heavy in the accent.
- Keys (rows on `ochazuke.timeline`): `enter`/`space` toggle, `l`/`h` open/close, `z o`/`z c`/`z a`, `z R`/`z M` all, `z 1`–`z 9` fold a section, `J`/`K`/`ctrl+e`/`ctrl+y` scroll line-wise, `G` the end.
- Data in: `SetCards` keeps selection, open cards and folds by id; `Patch(cards...)` updates or appends cheaply for streaming. Bodies render lazily (open and on screen), cached by id, width, `Revision` and folds; a frame costs the same at 500 and 5000 cards (`BenchmarkTimeline`).

- Sections are tabs across the top instead of a rail, so the rows get the whole width. `tab` and `]` show the next section, `shift+tab` and `[` the previous, wrapping (`settings.section {step}`, or `{name}`); each section keeps its selected row. With one section there is no tab row.
- One row per setting: its name on the left, its value on the right. There is no header and no Value/Default/Source columns. A `•` after the name marks a value that is not the default. `‹ value ›` marks a value `h`/`l` steps.
- The description under the rows says what the default is and where the value comes from: not in settings.json, set in settings.json, or settings.json holds an invalid value (with the reason) so the default applies.
- List settings: a list setting's row shows its item count (`(none)` when empty), and each item is a row directly beneath it with the name column blank. On a list's row `enter` or `n` adds an item at the end. On an item row `enter` or `i` edits it, `n` adds one after it, `d d` deletes it and `r` resets the whole list. An empty item is refused.
- `u` (or `ctrl+z`) takes back the last change made on the page and shows its row. A value that was invalid in settings.json comes back as it was. `u` is offered only when there is a change to take back.
- `backspace` and `delete` reset a setting, as `r` does.
- The page reopens on the section and row it was left on.

### State cache and deltas

- A state verb run through `cli.Shell` takes `--since LIST=HASH,...` and `--since-cache ID` (`cli.StateFlags`, `FormatSince`/`ParseSince`; `--since=` asks for every list in full, with hashes) and answers JSON Lines: a header `{"state":1,"cache":ID}`, then per list `unchanged`, a `delta` (the changed and added rows whole at their indexes, the removed ids) or the list in `full`, each with its content hash (`RecordHash`, `ListHash`). An unknown hash, another cache id or a pruned version answers full, never wrong. The catalog declares `stateDelta: 1`.
- The extension side caches each list's last versions (`Shell.StateCache`): `(id, record hash)` files under `$XDG_CACHE_HOME/<bin>/state/<scope>/lists/<list>/`, written temp + rename and content-addressed, `Keep` (2) versions per list and `Scopes` (8) scopes, the rest deleted. `StateCache.Scope(args)` adds to the scope (a TUIOS server); `StateCache.Fingerprint(args)` (`StatFingerprint(paths...)`) answers an unchanged poll without running the verb, except under `--fresh`; `StateCache.Off` turns it all off.
- `MountPage` uses it: with `PageConfig.FetchFlags` a page's `Reload` sends its list hashes and applies the answer (`PageView.ApplyState`): unchanged touches nothing and skips `OnRows`, a delta goes through `List.Patch`, full through `SetRows`; a list whose hash does not match after applying is fetched again in full, once. `PageView.Refresh` forgets the hashes. An older extension (no `stateDelta`) keeps full answers through `Fetch`.
- `List.Patch(ListPatch{Upsert, At, Remove})` (and `PatchItems`) is `SetItems` over the patched rows: kept rows keep their instances, selection and marks, and only removed rows close. `SetItems` keeps a table's measured widths when every row draws the same cells.
- `cli.DecodeState` and `RowReader.Answer()` read a delta answer. Benchmarks `BenchmarkStatePoll` and `BenchmarkStateApply` cover an 8,000-row poll, unchanged and with one row changed.

### Builtin verbs

- Every ochazuke tool's catalog lists the framework's verbs beside the tool's, and some are application verbs (the outline's 14, the chooser's 3), so hosts mounted them as the tool's (`ai-outline`, `qbt-outline`). `Operation.Builtin` now marks every operation the framework registers: everything `NewRuntime` and `NewModel` register, and what a framework constructor registers later (`NewPicker`, `NewPalette`, `NewAppearance`, `grid.Register`, `markdown.Register`, `cli.AddCommands`). ### Every list filters

- `/` on a focused list (page lists, tables, catalog lists, the Settings page's section, a list in a modal) opens a query line above the rows; typing keeps the rows whose label or cells hold every word, ignoring case, in list order, `N of M` on the right. In the `list_filter` mode up/down and `ctrl+n`/`ctrl+p` move among the matches (no spill), enter keeps the filter (`/` edits it, `esc` clears it), esc clears it and selects the row `/` found, backspace on an empty query leaves, `ctrl+u` empties it.

## v0.3.0 (2026-10-26)

Requires oden v0.1.1. A minor release: new public API (`Column.Wrap`, `Column.Max`, `ListItem.Section`, `Binding.FromRow`).

### Highlights

- Tables wrap long cells (`Column.Wrap`), cap flexible columns (`Column.Max`) and draw section labels (`ListItem.Section`).
- Binding rows can pass the acted-on row's data as an argument (`Binding.FromRow`, `"row:<field>"` in binding files).
- Confirm prompts for CLI calls without a target read the request's arguments instead of naming `app`.
- The `?` help is a list table (`helpColumns`: key, operation, arguments, description) instead of its own column layout: a header line, the selected row as the reverse highlight alone (no `> ` marker), section labels and wrapping from the table. Content and order are unchanged.

### API changes

- `Column.Wrap`: in `List.View` a long cell wraps onto further lines of its row instead of being cut (`TableText` still cuts). `Column.Max` caps a flexible column's growth. Both are in the catalog's `columns` (`wrap`, `max`).
- `ListItem.Section`: a table draws a label line above each run of rows in one section, repeated at the top of a window that starts inside it.
- Confirm prompts without a target instance: a request that addresses no instance of the verb's noun (a CLI call with positional words) expands `{{noun}}` to the verb's noun and `{{id}}`, `{{target}}`, `{{label}}` to the argument of that name, else its first argument in `ParameterOrder`, instead of naming `app` (o-git gap).
- `Binding.FromRow(arg, field)` (`SourceRow`; `"row:<field>"` or `"row"` in a binding file's `from`): a binding row passes the acted-on row's `Data` as an argument (a map key or struct JSON field, dotted for nested values; the whole value JSON-shaped), reading the focused row also when the row is bound on the list; a missing field leaves the argument out, and `ValidateBindings` rejects a malformed field (o-git gap).

## v0.1.1 (2026-10-25)

Requires oden v0.1.1. Fixes from mtm's test pass:

- `Tree.Record(TreeAction{ID, Label, Undo, Redo})`: an application change kept outside the nodes (a task status) goes on an outline's undo stack in order with the tree's edits. Story `tree/undo-app-action`.
- The footer shows only the newest notice, cut to half the width with `(+N more)`, so notices never hide the hints. Story `notices/footer-keeps-hints`.
- An argument error (`ArgumentError`, `Response.Argument`) adds no `pass --target, one of: …` hint in the CLI.
- `?` help: a row's `Help` replaces its operation's description (the `"`, `q`, `@` and count rows now say what they do); a generated prefix cancel (`d esc`) is listed only while a sequence on its prefix answers.

## v0.1.0 (2026-10-25)

First tagged release. Requires Go 1.26 and oden v0.1.0.

- Bubble Tea v2 application framework: retained pages, nouns and instances, one focus field and one global mode, one stack walk for actions and bindings, binding rows (`Define`, bindings files, capture rows, verb guards), `ValidateBindings`.
- Components: lists and tables (lists with columns), the tree and outline editor (`AddTree`), modal text inputs with an undo tree, registers and macros, the file picker, terminal instances, partial-screen modals and confirm prompts.
- Chrome: the ex-mode command line and palette with parameter choices, footer hints as `key noun.verb`, `?` bindings help, a notice line and the two-row jobs ticker.
- Runtime: operations with a delivery contract for off-loop jobs, action history with dot-repeat, tree queries, and live control over a Unix socket.
- `cli`: the generic NOUN VERB shell, the catalog answer and `cli.Mount` into oden command groups.
- `story` and `o-story`: stories as data played headless against the real chrome, and session recordings.
