# Changelog

Generated by o-inventory from the snapshots in ~/hub/inventory: one entry per snapshot, newest first, only the concepts that changed. Every line but Commits is derived from the diff; `fixed:` lines quote `fix:` commit subjects.

## v0.5.0 (2026-10-26)

A minor release: inline completion for inputs, a preserved-newlines option for Markdown, and `Runtime.Bind` no longer cancels a key sequence it does not touch.

### Highlights

- Inline completion: an application gives an input triggers such as `@`, `$` or `[[`, each with an asynchronous search. Typing a trigger at the start of a token offers the search's suggestions for the rest of the token in a list drawn under it, while typing keeps editing the same input.
- The token runs from the trigger to the next whitespace (`/` never splits it); the query is the whole token after the trigger, wherever the cursor is inside it. Of overlapping triggers (`[` and `[[`) the longest wins.
- Accepting replaces the whole token and keeps the trigger (`@src/ma` becomes `@src/main.go`) as one undoable edit.
- Searches run off the loop after a 150 ms pause in typing. An answer to a request older than the one on screen is dropped, so a slow, late answer never replaces a newer one; a search error is shown in the list.
- Keys while the list is open: `ctrl+n`/`ctrl+p` or `down`/`up` move, `tab` takes the highlighted suggestion (else the first), `enter` takes it only once one is highlighted (so enter after a typed token still submits or breaks the line), `esc` hides the list and stays in insert. `tab` on a token with the list closed opens it at once, unless the application binds `tab` itself.
- The demo's notes field completes `@` library entries, `$` skills and `[[` pages. o-story stories `completion/*` (typing-opens, look, accept-undo, escape-stays-insert, error-row, mid-token-tab, longest-trigger); a story input takes `completions: [{trigger, items, fail}]`.
- Markdown keeps line breaks on request: `markdown.PreserveNewlines()` makes every newline inside a paragraph a line break (Glamour's `WithPreservedNewLines`), for notes written as plain lines. Long lines still wrap; code blocks and tables draw the same. A Doc with the option keeps its items, highlight and byte-exact toggles. o-story stories `markdown/preserve-newlines` and `markdown/render-preserve-80`.
- `Runtime.Bind` and the builder's `Define(noun).Mode(m).Bind` while a key sequence is pending (`d` of `d d`) keep the sequence unless a row they add or replace is on it: in its mode, with keys equal to, extending or extended by the keys typed so far. Before, any new row cancelled it, so an application binding rows mid-sequence broke `d d`.

### API changes

- `Completions(triggers...)` (an `InstanceOption` read by `AddInput`) and `NounBuilder.Completions(triggers...)`; `Input.Completions`; `Runtime.CompletionTriggers(id)` (the input's own, else its noun's). A trigger must be non-empty, hold no whitespace and have a search.
- `CompletionTrigger{Trigger, Search}`, `CompletionSearch func(ctx, query) ([]Suggestion, error)`, `Suggestion{Text, Label, Detail}`, `SearchStrings(func(ctx, query) ([]string, error))`.
- `FindCompletionToken(text, cursor, triggers) (CompletionToken, int, bool)` and `CompletionToken{Start, End, Trigger, Query}`.
- `Runtime.Completer() *Completer`: `Open`, `Input`, `Token`, `Suggestions`, `Err`, `Highlighted`, `Searching`, `State`, `Debounce`, `DebounceTick`, `DebounceCurrent`; `CompletionDebounceMsg{Seq}`, `DefaultCompletionDebounce`, `CompletionNoun`.
- The `completion` noun: `completion.open` (guard `completion-available`), `completion.move {delta}` (a motion), `completion.accept`, `completion.dismiss`; rows in insert mode on the noun (`esc`, `tab`, `enter`, `ctrl+n`, `ctrl+p`, `down`, `up`) and `tab` → `completion.open` on the editor noun. Guards `completion-rows` and `completion-highlighted`.
- The stack walk reads a focused instance's inner level first (the open suggestion list); nothing else sets one.
- `markdown.Option` and `markdown.PreserveNewlines()`; `markdown.Block(text, width, appearance, opts...)` and `markdown.New(r, id, parent, src, opts...)` take options (existing calls compile unchanged). Renderings are cached per option. A story's markdown spec takes `preserveNewlines`.

### Migrating

- The Markdown option needs no change. An application that relied on `Bind` clearing a pending sequence after binding an unrelated row now keeps the sequence; one that binds a row on the sequence still has it cancelled.
- Completion needs no change: `tab` in insert mode on an input with no triggers is unchanged (the new editor row's verb is guarded off there). An application that binds `tab`, `enter`, `esc`, `up`/`down` or `ctrl+n`/`ctrl+p` on an input with triggers keeps them while the list is closed; while it is open the list's rows answer first.

## v0.4.0 (2026-10-26)

Requires oden v0.1.1. A minor release: UI services on `Ctx` for telling the user something from a handler, resizable list/detail panes, and a new `markdown` package. Two behavior changes to check when upgrading: `Model.Notify` now returns a `NoticeID`, and a key clears `Model.Status` before it runs rather than after.

### Highlights

- UI services on `Ctx`: handlers say what to tell the user (`ctx.Notify`, `ctx.ClearNotice`, `ctx.Status`) and each host decides how to show it: the footer in the TUI, stderr on the CLI, `Response.Messages` on a socket or API call. No `Runtime.Model`.
- Notices and status lines now print on the CLI: `cli.Shell` writes `notice: TEXT` and `status: TEXT` on stderr beside its `warning:` lines, and `ochazuke NOUN VERB` prints a call's messages the same way.
- Resizable panes: in normal mode `>` grows a page's list pane, `<` shrinks it, `=` resets the divider; counts repeat (`3>`). Steps of 5% of the split, at most 30 points either way, each side keeps 16 cells (3 rows stacked), so neither pane collapses; stacked (narrow) layouts resize the lists over the detail the same way. The keys answer, and the footer shows `>/< resize`, only on a page whose last frame drew a split (guard `pane-split`).
- The divider is remembered per page in `panes.json` in the state directory (`Config.PanesPath()`, atomic writes); nothing is written when the config is disabled. A file that does not parse, or a write that fails, is a footer notice.
- Splits read it: `Layout.Split`, `SplitBlock` and `SplitFocusBlock` divide by `Layout.Shift`, which `Runtime.PaneLayout(page, layout)` sets from the page; `Layout.Divide` does the same for a split drawn by hand. Catalog pages with a detail (`cli.MountPage`) and the demo's Library get it with no application code.
- Markdown, in a new package `markdown`: `markdown.Block` renders with Glamour v2 in the appearance's style, and `markdown.Doc` is a document whose task items you move between with `j`/`k`, toggle with `x` and undo or redo with `u`/`ctrl+r`. Each change is saved back to its source by rewriting only the box character. A toggle of an item that is gone or changed in the source is refused with an error and nothing is written. The demo has a Checklist page.
- o-story: `"state": true` gives a story its own state directory, `{"restart": true}` rebuilds the session into it, and the `shift` expectation reads the page's divider; stories `panes/*` (grow, shrink, clamp, stacked, remembered, no-split) and `markdown/*` (render, toggle, refind, refused, moves, spills).

### API changes

- `ctx.Notify(text) NoticeID`, `ctx.ClearNotice(id)`, `ctx.Status(text)`; the same on `Runtime.UI()` (`*UI`) for code without a `Ctx` (setup, daemon events).
- `UISink` (`Notify(id, text)`, `ClearNotice(id)`, `Status(text)`) and `UI.Attach(sink) UISink` (returns the previous sink; nil detaches), `UI.Sink()`. With no sink messages are discarded, except that the last 32 posted before the first attach (the startup ring) are replayed into that sink, then dropped.
- `UIMessage{Kind, ID, Text}` (kinds `UINotice`, `UIClearNotice`, `UIStatus`, `UIMessage.Apply(sink)`) and `RecordingSink` (`Messages`, `Notices`, `LastStatus`) for tests.
- `NewModel` attaches the `Model` as the sink: notices go to the footer and the status line as before. `Model.Notify(text)` now posts through the UI and returns the `NoticeID` (it returned nothing).
- A key clears `Model.Status` before it runs, so a status its handler sets (`ctx.Status`) stands until the next key; before, a successful key cleared it afterwards. A key's error still replaces it.
- `Response.Messages` (`messages`, omitempty): what a `HandleCall` (socket or API) call posted while it ran, also sent to the runtime's sink. `CallResponse(ctx, path, q)` returns the whole `Response`; `Call` is unchanged.
- The `UI` component is an instance (`__ui`) under `app`; `Runtime` gains no field.
- Panes: `Layout.Shift`, `Layout.Divide(first, total, least)`, `Runtime.PaneLayout`, `Runtime.PaneShift`, `Runtime.SetPaneShift`, `Config.PanesPath`, `PanesFile` and the constants `PaneStep`, `PaneShiftLimit`, `PaneMinWidth`, `PaneMinHeight`; operations `pane.grow`, `pane.shrink {steps, page}` and `pane.reset {page}`, rows `>` `<` `=` on `app` in normal mode.
- `markdown.Block(text, width, appearance)` and `markdown.StyleOf(appearance)`: Glamour's standard `dark` or `light` style from the appearance's background, `notty` under mono and NO_COLOR. Renderings are cached by text, width and style.
- `markdown.New(r, id, parent, src)` returns a `*markdown.Doc` (`View`, `Toggle`, `Undo`, `Redo`, `Reload`, `Tasks`, `Selected`, `Select`, `Focus`, `ListID`). It is on the `markdown` noun (`markdown.toggle`, `markdown.undo`, `markdown.redo`, `markdown.reload`; `x`, `u`, `ctrl+r` in normal mode), with `markdown-task` rows.
- `markdown.Source{Load, Save}` and `markdown.File(path)`, which writes atomically. Before a toggle the source is loaded again and the item found again by its text; when it is gone, changed or ambiguous the toggle, undo or redo fails with an error wrapping `markdown.ErrRefused` (the CLI exits non-zero; the TUI shows it as the key's error in the footer status), and the view shows the source as it is now.
- `markdown.Tasks(text)` lists task items with the byte offset of each box (goldmark with GFM, as Glamour parses).
- `Appearance.Background()` reports the resolved background (`light` or `dark`) and whether the appearance is plain.
- Dependencies: `charm.land/glamour/v2` v2.0.1 and `github.com/yuin/goldmark` v1.7.8 (with chroma, bluemonday and goldmark-emoji indirect). Lip Gloss stays v2.0.6 and Bubble Tea v2.1.0.

### Binary size

- `markdown` is a package of its own, so only a binary that imports it carries Glamour, goldmark and chroma. The demo binary (`cmd/ochazuke`, which imports it for the Checklist page) grows from 10.2 MB to 20.0 MB, mostly chroma's lexers; `examples/hello`, which does not, is 9.4 MB as before (+37 KB for the UI and panes code). Measured with `-trimpath` on darwin/arm64.

### Migrating

- In a handler, `a.m.Notify(x)` becomes `ctx.Notify(x)` and `a.m.Status = x` becomes `ctx.Status(x)`; keep the returned `NoticeID` to `ctx.ClearNotice(id)` instead of editing `Model.Notices`.
- Without a `Ctx` (setup, a daemon event), `a.r.UI().Notify(x)` / `a.r.UI().Status(x)`.
- A caller of `Model.Notify` that used it as a statement keeps compiling; one that passed it as a `func(string)` needs a wrapper.
- Tests that asserted on `m.Notices` keep working with a `Model`; without one, attach a `RecordingSink`.
- `>`, `<` and `=` are new default rows on `app` in normal mode (guarded by `pane-split`); an application with its own rows on those keys should check `bindings list` on its split pages.

## v0.3.0 (2026-10-26)

Requires oden v0.1.1. A minor release: new public API (`Column.Wrap`, `Column.Max`, `ListItem.Section`, `Binding.FromRow`).

### Highlights

- Tables wrap long cells (`Column.Wrap`), cap flexible columns (`Column.Max`) and draw section labels (`ListItem.Section`).
- Binding rows can pass the acted-on row's data as an argument (`Binding.FromRow`, `"row:<field>"` in binding files).
- Confirm prompts for CLI calls without a target read the request's arguments instead of naming `app`.
- The `?` help is a list table (`helpColumns`: key, operation, arguments, description) instead of its own column layout: a header line, the selected row as the reverse highlight alone (no `> ` marker), section labels and wrapping from the table. Content and order are unchanged.

### API changes

- `Column.Wrap`: in `List.View` a long cell wraps onto further lines of its row instead of being cut (`TableText` still cuts). `Column.Max` caps a flexible column's growth. Both are in the catalog's `columns` (`wrap`, `max`).
- `ListItem.Section`: a table draws a label line above each run of rows in one section, repeated at the top of a window that starts inside it.
- Confirm prompts without a target instance: a request that addresses no instance of the verb's noun (a CLI call with positional words) expands `{{noun}}` to the verb's noun and `{{id}}`, `{{target}}`, `{{label}}` to the argument of that name, else its first argument in `ParameterOrder`, instead of naming `app` (o-git gap).
- `Binding.FromRow(arg, field)` (`SourceRow`; `"row:<field>"` or `"row"` in a binding file's `from`): a binding row passes the acted-on row's `Data` as an argument (a map key or struct JSON field, dotted for nested values; the whole value JSON-shaped), reading the focused row also when the row is bound on the list; a missing field leaves the argument out, and `ValidateBindings` rejects a malformed field (o-git gap).

## v0.2.0 (2026-10-26)

Requires oden v0.1.1. A minor release: `Response.Result` changes type, and the shell, the `Model` and the default keys gain behaviour hosts should know about.

### Highlights

- User configuration for every app: `bindings.json`, typed `settings.json` with an in-place editor, `actions.json` (external commands as verbs), user colour schemes (`themes.json`) and a persisted action history, under `~/.config/<app>` and `~/.local/state/<app>`.
- New framework components: the chooser (`Runtime.OpenChooser`) and the `'` page picker (recent pages first), schema-driven record editors (forms written as you type, with suggestions), scrollable page details, and catalog-declared data pages with widgets that a host mounts without the extension's Go code.
- The oden TUI seam: `cli.TUI(app)` gives any oden tool a Commands page whose commands run in an attached pseudo-terminal (`cli.StartPty`).
- CLI output formats: `--format json|table|markdown|toon` on every shell command.
- `?` help shows each row's arguments; palette commands that return a list of objects open a read-only Results table.
- Counts on `list.move`, the jobs ticker on the footer rule, a configurable terminal leader, linear-time list and tree updates.

### API changes

- `HandleCall` returns `Response.Result` as a `json.RawMessage` (the handler's value encoded once, so object keys keep the order the value marshals in; `Lines` stays `Lines`; a nil or null result is nil). Code that type-switched on the decoded `map[string]any`/`[]any` must unmarshal the bytes itself (`fix/cli-gaps`).
- `Layout.BodySizeWith(f)` now equals `Layout.BodySize()`: the jobs ticker takes no row, it rides the rule line above the footer (`Layout.TickerRule`). Kept for callers; new code can call `BodySize` (`fix/uxr2-batch`).
- `Model.Init` now loads the user bindings file and the settings and batches the settings poll with `tea.RequestBackgroundColor`. A host that drives the `Model` without calling `Init` (headless tests) gets neither.
- New default row: `'` on `app` in normal mode runs `page.pick` (only with no modal open). An app that bound `'` keeps its own row.
- `HelpRow` gains `Args` (the row's arguments, resolved when help opens), so code comparing whole `HelpRow` values sees the new field.
- The framework now registers the `chooser` noun: an app that registers its own (mtm's `cmd/mtm/chooser.go`) must drop it, or registration panics.

### The oden TUI seam (`feat/oden-seam`)

- `cli.StartPty` / `cli.PtyStream`: a `TerminalStream` for a local process, run in a pseudo-terminal (`charmbracelet/x/xpty`) and emulated with `charmbracelet/x/vt`; frames carry the cursor cell, shape and visibility; `Resize`, keys and bracketed paste reach the program; `Release` hangs up and kills the process group and closes the pty, once. New dependencies: `x/xpty` v0.1.4 (with `creack/pty`), `x/vt` v0.1.0.
- `cli.AddCommands` / `CommandSource` / `OdenCommands`: the `command` noun and a Commands page over an oden tool's catalog (inline commands and `<bin>-<name>` on PATH, with shadowing); `command run` opens the command in a terminal under its row, attached (`ctrl+a d` detaches), `command help` shows its help in the detail (an external's `--help` as a job), `which`, `stop` (confirmed).
- `cli.TUI(app)` as an oden `Default` gives any oden tool that page; `cli.NewCommandsModel` for hosts and smoke runs. `examples/hello` uses it.
- o-story: a page with `commands` is the Commands page; stories `commands/*`.

### Lists, help and the ticker (`fix/uxr2-batch`)

- Counts on `list.move` (`3j`, `5k`): moves that many rows, stops at the edge, spills as one move only from the edge.
- A focused empty list draws `(empty list)` reversed, so a spill into it shows where the focus went.
- `?` help hides a row whose guard is false at the focus, as the footer and the walk do; `bindings list` keeps it.
- The jobs ticker rides the rule line above the footer (`── noun.verb running · …`) instead of taking rows, so a job never moves or hides the body. Story `ticker/keeps-body`.

### CLI (`fix/cli-gaps`)

- A `.Quiet()` verb's job prints no `job #N` line unless it fails.
- Immediate results keep the handler's key order (the `Response.Result` change above); o-csv no longer needs Pending verbs for header order.
- A bare `--json` (last, or before another flag) asks for the JSON output the shell always prints and is ignored, instead of eating the next word as arguments.

### CLI output formats (`feat/cli-format`)

- `--format json|table|markdown|toon` on every shell command (`cli.Formats`; json stays the default, byte for byte). A list or state verb's rows (an array of objects, `Lines` of `Row` included) print one table per noun: the noun's declared columns over the rows' `cells`, else the records' fields (id and label first, data's fields last).
- `table` cuts with `…` and drops columns by `Priority` only when stdout is a terminal (`Shell.Width` overrides); `markdown` is a GitHub table; `toon` is `NOUN[N]{col,...}:` and a line per row, quoting only values with a comma, a quote or a line break (the o-qbt rule). A non-tabular result prints JSON with a stderr note.
- `--format` combines with `--json '{...}'`; a bare `--json` with another format is an error; a verb with its own `format` parameter (o-qbt, o-ai) keeps `--format` as that argument.
- `ochazuke.TableText(cols, rows, width)`: the list's column layout as plain text lines (width 0: no cut).

### Page details (`feat/detail-scroll`)

- `Runtime.AddDetail(id, item func() string, Parent(page))`, `Runtime.Detail(id)`, `Detail.Window(text, width, height)` (wraps, windows, returns a `12–40 / 300` marker), `Detail.Scroll`/`Offset`/`Overflows`/`Marker`/`Item`.
- `detail.scroll` on `J`/`K` (app rows, counts work, guarded by `detail-scrolls`): the detail scrolls while the list keeps the focus; an inner `J`/`K` (the outline's moves) answers first; a new item starts at the top. The footer shows one `J/K detail` hint only while the detail overflows (a motion row with its own `Hint` now shows). Demo: a Library page.

### Many pages (`feat/many-pages`)

- The tab row windows around the active tab with `‹N` and `N›` counts for the pages hidden on each side.
- The framework chooser, lifted from mtm: `Runtime.OpenChooser(ChooserSpec{Kind, Title, Rows, Filter, Choose, Create, CreateLabel, CreateRow, Empty})`, `Runtime.Chooser(kind)`, `ChooserRow`, `Chooser.SetRows`/`Matches`/`Highlighted`/`Query`/`Moved`; keys are rows on the `chooser` noun (insert pinned). mtm must delete `cmd/mtm/chooser.go` when it adopts this version: both register the `chooser` noun, and a second registration panics.
- `ChooserSpec.Keep []int` (from mtm, UX review 2 F22): the cell columns a narrow chooser cuts last; the other columns narrow to their minimum (6) first. mtm's directory chooser passes `Keep: []int{1}` (the path).
- `ChooserSpec.Preview func(ChooserRow) string` and `ChooserPreviewMin` (60), from mtm's context picker: from that width the highlighted row's preview is drawn on the right (three fifths rows, the rest preview, a fixed-width column so the panel does not resize as the highlight moves; wrapped, cut with `…`); narrower, no preview.
- The page picker: `page.pick`, `Runtime.OpenPagePicker()`, on `'`; every page, the ones visited before most recent first, then the never-visited in registration order, then the current page last, marked `current`, so `'` enter goes back to the page last left; type to filter, enter opens, esc closes. Story `picker/page-picker-recent-first`.

### User configuration (`feat/user-config`)

- Every app loads `~/.config/<app>/bindings.json` (`$XDG_CONFIG_HOME/<app>`) at start: `Runtime.Config()` (`Config{App, Dir}`, `Path`, `Directory`, `Disable`, `BindingProblems`), `Runtime.EnsureUserBindings`/`ReloadUserBindings`/`CheckUserBindings`, verbs `bindings.reload|path|check`; a bad row becomes a notice, never a crash. The CLI applies the same file. Constants `BindingsFile`, `SettingsFile`.
- Declared typed settings in `settings.json`: `Runtime.DeclareSetting(Setting{Name, Type, Default, Description, Enum})` (string enums, integer, number, boolean, duration), `Runtime.Settings()` with `Int`/`String`/`Bool`/`Float`/`Duration`/`Value`/`Get`/`Set`/`Reset`/`List`/`Observe`/`Reload`, `settings.*` verbs, atomic writes, a 1 s poll (`SettingsPoll`, `SettingsPollMsg`) only when settings are declared.
- `settings.edit`: an in-place settings editor modal (a table of `setting` rows, every key saves at once; no default key). The demo's theme and density are settings.

### User actions (`feat/config-actions`)

- `actions.json` beside `bindings.json` (`ActionsFile`): each entry adds a verb to an existing noun that runs an external command, an application verb like any other (binding rows, the palette, the CLI, `?` help, the catalog). `Action{Noun, Verb, Description, Command, Base, Call, Target, JSON, Label, Confirm, Parameters, Positional, Dir, Timeout, Quiet}`, `Argv`; `Runtime.EnsureUserActions`/`ReloadUserActions`/`UserActions`, `Config.ActionProblems`; verbs `actions.list|reload|path`. `Model.Init`, `cli.Mount` and `cli.Shell.Run` install the file before the user bindings.
- `command` is an argv template run without a shell and without stdin; `base` is the JSON convention `BASE NOUN VERB --json ARGS [--target T]` (`call` renames the noun and verb). Templates: `{{target}}`/`{{id}}`, `{{label}}`, `{{noun}}`, `{{verb}}`, `{{data}}`, `{{data.KEY}}`, `{{args}}`, a parameter; an empty lone placeholder word is dropped. The work is a `Pending` job labelled `label` (default the program); stdout is the result (JSON, JSON Lines as a list, else text), a non-zero exit fails with stderr's last line, `timeout` kills it.
- A malformed entry is skipped and is a notice (a CLI `warning:`). Commands come only from the user's own file, never from a catalog, a row or a call; the catalog never carries a command (README "User actions").
- A confirm prompt's `{{target}}` now expands to the instance id, as `{{id}}` does.

### Terminal leader setting (`feat/config-actions`)

- `terminal-leader` (`TerminalLeaderSetting`, default `DefaultTerminalLeader` `ctrl+a`): the terminal leader is a declared setting, one `ctrl+` or `alt+` key. `Runtime.EnsureTerminalLeader()` declares it unless the app did and applies settings.json's value and every later change; an app with terminals calls it at setup (`cli.AddCommands` and the full-project example do), so an app without terminals never lists it. `EnsureConfigSettings` (Init) applies an app-declared one. `Runtime.SetTerminalLeader(key)` rewrites the rows (every noun's single-key `leader_pending` entry row with its prefix and timeout request, the self-send row, hints naming the old leader); application `leader_pending` rows stay. `Runtime.TerminalLeader()`. `AddTerminal` applies it, so leader rows defined after `Init` move too. The old leader is ordinary input to the pane.
- `Setting.Validate` (code only): a further check after the type; `Set` refuses a value it rejects, a file value it rejects reads the default.
- o-story: the attached pane's line names the current leader; stories `terminal/leader-twice-sends-one`, `leader-unbound-forwards-both`, `leader-timeout-sends-leader`, `leader-setting-footer`, `leader-setting-detach`.
- mtm: its leader row moves with the setting, but `terminal.keys`' modal labels still print `ctrl+a` literally; it should read `Runtime.TerminalLeader()`.

### Record editor (`feat/record-editor`)

- Schema-driven forms written as you type: `RecordSpec{Title, Fields, Load, Save, Debounce, Insert, OnLeave}`, `RecordField{Name, Label, Parameter, Multiline, Validate}`, `RecordFields(op)` from a verb's parameters, `Runtime.AddRecordEditor` (placed on a page) and `Runtime.OpenRecordEditor` (a modal), `Runtime.RecordEditor(id)`, `Record`, `RecordWrite`, `RecordDebounceMsg`, `DefaultRecordDebounce`. Invalid values are never written; enum, sourced and boolean fields are chosen from a list; `u`/`ctrl+r` undo and redo as writes; no save key. Nouns `form`, `form-field`, `form-text`, `form-choice`, `form-option`.
- `ModalBody` (`ModalTitle`, `ModalBlock`): a modal whose component draws itself needs no `ModalView`. The record editor, its choice list and the framework `Chooser` draw through it.
- `Appearance.Accent` (code only) overrides the theme's accent colour, e.g. for a pin state; mono and `NO_COLOR` stay colourless.

### Form suggestions and page row hooks (`feat/form-hooks`)

- Record editor: a field whose `Parameter` is `Free` with `Enum` or `Source` is a text field with suggestions (noun `FormSuggestNoun`, `form-suggest`): typing stays free text and a value outside the suggestions is written as typed; `enter` (normal) or `ctrl+space` runs the new verb `form.suggest`, which opens the framework chooser (`FormSuggestionsKind`, `form-suggestions`) over the Enum then the Source verb's result, loaded off the loop as a job of the chooser when the Source is Pending; a pick (or the typed query, `+ use "…"`) fills the field and is written at once. Before, such a field was plain text with no suggestions (mtm's tool forms lost their pick lists). Such a field is one line high. Story `forms/suggestions`.
- `cli.PageConfig.OnRows func(list string, rows []cli.Row)`: runs on the loop after a list's rows land (a reload's answer, a state answer filed under each list, an empty one included, or the host's `SetRows`/`SetState`), with the rows as filed; a failed load does not call it. A host follows a list's rows without wrapping `Reload` (nabe's `followReload`).

### List scaling (`fix/list-scaling`)

- `SetItems` removes dropped rows in one batch (one child index for the batch, not a tree scan per row), trees index node positions, depths and child counts, and tables measure their cells once per item set and draw only the window. Benchmarks in `scaling_test.go` (`SetItemsReplace`, `TreeBuild`, `TreeExpand`, `TableView`) now scale linearly.

### Integration fixes

- `'` (`page.pick`) answers only with no modal open (guard `no-modal`). Without the guard it opened the page picker over `?` help, the settings editor and a record editor, and choosing a page then failed. Story `picker/page-picker-not-in-modal`.
- The catalog's `free` flag is now pinned by a test and documented on `CatalogVerb`. A free sourced parameter (mtm's `--model`) is published as `"free": true`, so a host (nabe) can tell it from a closed one. The field was already written through `ochazuke.Parameter`'s JSON tag; nothing tested or documented it.

### Small gaps (`fix/small-gaps`)

### Persisted history and colour schemes (`feat/history-themes`)

- The action history persists per app: `history.jsonl` in the state dir (`Config.StateDirectory()`: `Config.StateDir`, else `$XDG_STATE_HOME/<app>`, else `~/.local/state/<app>`; `Config.HistoryPath()`, `history.path`). `Model.Init` restores the last entries (`HistoryEntry.Restored`, before the session's own, so palette up/down recalls them and dot-repeat skips them) through `Runtime.EnsureHistory`; one writer goroutine appends off the loop and compacts at twice the limit (temp + rename); `Config.Flush` drains it on quit.
