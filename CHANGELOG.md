## v0.2.0 (unreleased)

Draft, from the `integrate/next` branch (branches on `3133e23` plus fixes). A minor release: `Response.Result` changes type.

### API changes

- `HandleCall` returns `Response.Result` as a `json.RawMessage` (the handler's value encoded once, so object keys keep the order the value marshals in; `Lines` stays `Lines`; a nil or null result is nil). Code that type-switched on the decoded `map[string]any`/`[]any` must unmarshal the bytes itself (`fix/cli-gaps`).
- `Layout.BodySizeWith(f)` now equals `Layout.BodySize()`: the jobs ticker takes no row, it rides the rule line above the footer (`Layout.TickerRule`). Kept for callers; new code can call `BodySize` (`fix/uxr2-batch`).
- `Model.Init` now loads the user bindings file and the settings and batches the settings poll with `tea.RequestBackgroundColor`. A host that drives the `Model` without calling `Init` (headless tests) gets neither.
- New default row: `'` on `app` in normal mode runs `page.pick` (only with no modal open). An app that bound `'` keeps its own row.

### The oden TUI seam (`feat/oden-seam`)

- `cli.StartPty` / `cli.PtyStream`: a `TerminalStream` for a local process, run in a pseudo-terminal (`charmbracelet/x/xpty`) and emulated with `charmbracelet/x/vt`; frames carry the cursor cell, shape and visibility; `Resize`, keys and bracketed paste reach the program; `Release` hangs up and kills the process group and closes the pty, once. New dependencies: `x/xpty` v0.1.4 (with `creack/pty`), `x/vt` v0.1.0.
- `cli.AddCommands` / `CommandSource` / `OdenCommands`: the `command` noun and a Commands page over an oden tool's catalog (inline commands and `<bin>-<name>` on PATH, with shadowing); `command run` opens the command in a terminal under its row, attached (`ctrl+a d` detaches), `command help` shows its help in the detail (an external's `--help` as a job), `which`, `stop` (confirmed).
- `cli.TUI(app)` as an oden `Default` gives any oden tool that page; `cli.NewCommandsModel` for hosts and smoke runs. `examples/hello` uses it.
- o-story: a page with `commands` is the Commands page; stories `commands/*`.

### Lists, help and the ticker (`fix/uxr2-batch`)

- Counts on `list.move` (`3j`, `5k`): moves that many rows, stops at the edge, spills as one move only from the edge.
- A focused empty list draws `(empty list)` reversed, so a spill into it shows where the focus went.
- `?` help hides a row whose guard is false at the focus, as the footer and the walk do; `bindings list` keeps it.
- The jobs ticker rides the rule line above the footer (`── noun.verb running · …`) instead of taking rows, so a job never moves or hides the body. Story `ticker/keeps-body`.

### CLI (`fix/cli-gaps`)

- A `.Quiet()` verb's job prints no `job #N` line unless it fails.
- Immediate results keep the handler's key order (the `Response.Result` change above); o-csv no longer needs Pending verbs for header order.
- A bare `--json` (last, or before another flag) asks for the JSON output the shell always prints and is ignored, instead of eating the next word as arguments.

### CLI output formats (`feat/cli-format`)

- `--format json|table|markdown|toon` on every shell command (`cli.Formats`; json stays the default, byte for byte). A list or state verb's rows (an array of objects, `Lines` of `Row` included) print one table per noun: the noun's declared columns over the rows' `cells`, else the records' fields (id and label first, data's fields last).
- `table` cuts with `…` and drops columns by `Priority` only when stdout is a terminal (`Shell.Width` overrides); `markdown` is a GitHub table; `toon` is `NOUN[N]{col,...}:` and a line per row, quoting only values with a comma, a quote or a line break (the o-qbt rule). A non-tabular result prints JSON with a stderr note.
- `--format` combines with `--json '{...}'`; a bare `--json` with another format is an error; a verb with its own `format` parameter (o-qbt, o-ai) keeps `--format` as that argument.
- `ochazuke.TableText(cols, rows, width)`: the list's column layout as plain text lines (width 0: no cut).

### Page details (`feat/detail-scroll`)

- `Runtime.AddDetail(id, item func() string, Parent(page))`, `Runtime.Detail(id)`, `Detail.Window(text, width, height)` (wraps, windows, returns a `12–40 / 300` marker), `Detail.Scroll`/`Offset`/`Overflows`/`Marker`/`Item`.
- `detail.scroll` on `J`/`K` (app rows, counts work, guarded by `detail-scrolls`): the detail scrolls while the list keeps the focus; an inner `J`/`K` (the outline's moves) answers first; a new item starts at the top. The footer shows one `J/K detail` hint only while the detail overflows (a motion row with its own `Hint` now shows). Demo: a Library page.

### Many pages (`feat/many-pages`)

- The tab row windows around the active tab with `‹N` and `N›` counts for the pages hidden on each side.
- The framework chooser, lifted from mtm: `Runtime.OpenChooser(ChooserSpec{Kind, Title, Rows, Filter, Choose, Create, CreateLabel, CreateRow, Empty})`, `Runtime.Chooser(kind)`, `ChooserRow`, `Chooser.SetRows`/`Matches`/`Highlighted`/`Query`/`Moved`; keys are rows on the `chooser` noun (insert pinned). mtm must delete `cmd/mtm/chooser.go` when it adopts this version: both register the `chooser` noun, and a second registration panics.
- `ChooserSpec.Keep []int` (from mtm, UX review 2 F22): the cell columns a narrow chooser cuts last; the other columns narrow to their minimum (6) first. mtm's directory chooser passes `Keep: []int{1}` (the path).
- `ChooserSpec.Preview func(ChooserRow) string` and `ChooserPreviewMin` (60), from mtm's context picker: from that width the highlighted row's preview is drawn on the right (three fifths rows, the rest preview, a fixed-width column so the panel does not resize as the highlight moves; wrapped, cut with `…`); narrower, no preview.
- The page picker: `page.pick`, `Runtime.OpenPagePicker()`, on `'`; every page in registration order, type to filter, enter opens, esc closes.

### User configuration (`feat/user-config`)

- Every app loads `~/.config/<app>/bindings.json` (`$XDG_CONFIG_HOME/<app>`) at start: `Runtime.Config()` (`Config{App, Dir}`, `Path`, `Directory`, `Disable`, `BindingProblems`), `Runtime.EnsureUserBindings`/`ReloadUserBindings`/`CheckUserBindings`, verbs `bindings.reload|path|check`; a bad row becomes a notice, never a crash. The CLI applies the same file. Constants `BindingsFile`, `SettingsFile`.
- Declared typed settings in `settings.json`: `Runtime.DeclareSetting(Setting{Name, Type, Default, Description, Enum})` (string enums, integer, number, boolean, duration), `Runtime.Settings()` with `Int`/`String`/`Bool`/`Float`/`Duration`/`Value`/`Get`/`Set`/`Reset`/`List`/`Observe`/`Reload`, `settings.*` verbs, atomic writes, a 1 s poll (`SettingsPoll`, `SettingsPollMsg`) only when settings are declared.
- `settings.edit`: an in-place settings editor modal (a table of `setting` rows, every key saves at once; no default key). The demo's theme and density are settings.

### User actions (`feat/config-actions`)

- `actions.json` beside `bindings.json` (`ActionsFile`): each entry adds a verb to an existing noun that runs an external command, an application verb like any other (binding rows, the palette, the CLI, `?` help, the catalog). `Action{Noun, Verb, Description, Command, Base, Call, Target, JSON, Label, Confirm, Parameters, Positional, Dir, Timeout, Quiet}`, `Argv`; `Runtime.EnsureUserActions`/`ReloadUserActions`/`UserActions`, `Config.ActionProblems`; verbs `actions.list|reload|path`. `Model.Init`, `cli.Mount` and `cli.Shell.Run` install the file before the user bindings.
- `command` is an argv template run without a shell and without stdin; `base` is the JSON convention `BASE NOUN VERB --json ARGS [--target T]` (`call` renames the noun and verb). Templates: `{{target}}`/`{{id}}`, `{{label}}`, `{{noun}}`, `{{verb}}`, `{{data}}`, `{{data.KEY}}`, `{{args}}`, a parameter; an empty lone placeholder word is dropped. The work is a `Pending` job labelled `label` (default the program); stdout is the result (JSON, JSON Lines as a list, else text), a non-zero exit fails with stderr's last line, `timeout` kills it.
- A malformed entry is skipped and is a notice (a CLI `warning:`). Commands come only from the user's own file, never from a catalog, a row or a call; the catalog never carries a command (README "User actions").
- A confirm prompt's `{{target}}` now expands to the instance id, as `{{id}}` does.

### Record editor (`feat/record-editor`)

- Schema-driven forms written as you type: `RecordSpec{Title, Fields, Load, Save, Debounce, Insert, OnLeave}`, `RecordField{Name, Label, Parameter, Multiline, Validate}`, `RecordFields(op)` from a verb's parameters, `Runtime.AddRecordEditor` (placed on a page) and `Runtime.OpenRecordEditor` (a modal), `Runtime.RecordEditor(id)`, `Record`, `RecordWrite`, `RecordDebounceMsg`, `DefaultRecordDebounce`. Invalid values are never written; enum, sourced and boolean fields are chosen from a list; `u`/`ctrl+r` undo and redo as writes; no save key. Nouns `form`, `form-field`, `form-text`, `form-choice`, `form-option`.
- `ModalBody` (`ModalTitle`, `ModalBlock`): a modal whose component draws itself needs no `ModalView`. The record editor, its choice list and the framework `Chooser` draw through it.
- `Appearance.Accent` (code only) overrides the theme's accent colour, e.g. for a pin state; mono and `NO_COLOR` stay colourless.

### List scaling (`fix/list-scaling`)

- `SetItems` removes dropped rows in one batch (one child index for the batch, not a tree scan per row), trees index node positions, depths and child counts, and tables measure their cells once per item set and draw only the window. Benchmarks in `scaling_test.go` (`SetItemsReplace`, `TreeBuild`, `TreeExpand`, `TableView`) now scale linearly.

### Integration fixes

- `'` (`page.pick`) answers only with no modal open (guard `no-modal`). Without the guard it opened the page picker over `?` help, the settings editor and a record editor, and choosing a page then failed. Story `picker/page-picker-not-in-modal`.
- The catalog's `free` flag is now pinned by a test and documented on `CatalogVerb`. A free sourced parameter (mtm's `--model`) is published as `"free": true`, so a host (nabe) can tell it from a closed one. The field was already written through `ochazuke.Parameter`'s JSON tag; nothing tested or documented it.

### Small gaps (`fix/small-gaps`)

- `Result.Label(label)` names one job of a verb (`Pending(work).Label("claude")`): `JobInfo.Label` in `jobs.list`, the ticker entry reads `noun.verb label state`, the shell's stderr line `job #N noun.verb label STATE`. Story `ticker/job-label`.
- `cli.CatalogDoc.ListColumns(noun)` and `CatalogDoc.RowSource(noun)`: the columns a host's list of a catalog noun's rows draws, following the row source verb (`rows`, else `list`) to the noun its rows answer to. A host mounts with `ochazuke.Columns(doc.ListColumns(noun)...)`; this is nabe's `columnsOf`/`rowSource`, which nabe can now drop.
- `bindings stops` (`Runtime.StopBindings`): the effective rows of every focus stop, app-wide, each read at the focus a jump lands on and in the mode it would have there: pages in tab order, stops in drawing order, open modals, then `app`. `bindings list --all` stays the export of every stored row; `stops` is what answers where.
- Fixed: focusing a list row instance (`SetFocus`/`focus.set`, `RetargetFocus`, a `FocusOnClose` landing, a page starting on a row, `Pop`) left the list's selection, and its highlight, on the old row while keys answered for the new one. The focused row is now selected. Story `lists/focus-set-selects-row`; `lists/one-highlight` checks the highlighted row is the focused one.
- Fixed: the confirm modal drew its keys twice, a hand-written `y yes · n no` under the prompt and the derived hint line (with `<any> key.ignore`). The body is the prompt alone and the swallowing row is hidden, so the hint line reads `y confirm.accept · n modal.pop`. Story `modals/confirm-one-hint`.
- `Page.OnOpen func(r, from)`: a page-opened hook, run on the loop each time `OpenPage` (page.open, page.next/previous, the picker) makes the page current from another page, after its focus and mode are restored; reopening the current page does not run it. Set it on the `*Page` `AddPage` returns.
- Fixed: a job launched from a chooser (`Choose` or `Create` returning `Pending`) failed with `unknown instance <kind>/query`, because picking closes the modal and its input before the callback runs. An application verb whose handler removed its own instance now launches on the nearest surviving instance of its old ancestry: the focus the chooser opened over.
- Changed: once a page has drawn a frame, a focus stop the last frame did not draw (a hidden panel) is skipped by `focus.next`/`previous` and list spills, instead of following the drawn stops; mtm no longer needs to mark a hidden tree `Unfocusable`. Before the first frame (the CLI) the walk is still tree order; a modal's stops are never skipped. An application view that draws a stop must call `Runtime.Placed` (the framework's views do). Story `motions/undrawn-stop-skipped`.
- `Layout.SplitFocusBlock(side, …)` with `SplitLeft`/`SplitRight`/`SplitNone`: a split whose focused panel is named (accent title and border; its cursor wins), for a view whose focus moves between panes (o-json). `Split`/`SplitBlock` keep the left focused. Story `chrome/split-focused-side`; o-story gains `layout: "split"` and the cell-exact `styled` expectation.
- `NoMarks()` (an `InstanceOption` for `AddList` and `AddTree`): a read-only view whose rows take no marks; `space` no longer answers with `list.mark` there (the verb is guarded by `list-marks`, so the footer and `?` leave it out) and `list.mark`/`List.ToggleMark` refuse. Replaces o-json's hidden `key.ignore` row. Story `lists/no-marks`.

### Persisted history and colour schemes (`feat/history-themes`)

- The action history persists per app: `history.jsonl` in the state dir (`Config.StateDirectory()`: `Config.StateDir`, else `$XDG_STATE_HOME/<app>`, else `~/.local/state/<app>`; `Config.HistoryPath()`, `history.path`). `Model.Init` restores the last entries (`HistoryEntry.Restored`, before the session's own, so palette up/down recalls them and dot-repeat skips them) through `Runtime.EnsureHistory`; one writer goroutine appends off the loop and compacts at twice the limit (temp + rename); `Config.Flush` drains it on quit. Unparsable lines are one notice and are dropped. Constants `HistoryFile`, `HistorySetting`.
- `history-limit` is a framework setting (`Runtime.EnsureConfigSettings`, called by `Model.Init` and the CLI shell, declares it unless the app did; 0 keeps none; it also bounds the ring). `Config.NoHistoryFile` opts an app out; a disabled config (stories, test binaries) keeps no file.
- The file keeps palette lines (failed ones too) and other completed operations, never text editing or its plumbing (the `input`, `editor`, `key`, `count`, `register`, `macro`, `yank-history`, `mode`, `palette` and `terminal` nouns), and never result values. Text-like arguments (`text`, `value`, `keys`, `args`, `password`, `secret`, `token`) are dropped unless the operation sets `Operation.PersistArgs` (`NounBuilder.PersistArgs()`; `settings.set` does), so a palette `command run deploy --token=…` does not write the token.
- Colour schemes: `Scheme` (roles `text`, `muted`, `accent`, `border`, `surface`, `error` as `SchemeColor{Light, Dark}`, plus `background`), `SchemeSet`/`NewSchemeSet`, `ParseSchemes`, `Appearance.Schemes`; `Appearance.Theme` names a built-in or a scheme. User schemes are `themes.json` beside `settings.json` (`ThemesFile`); a scheme that does not validate is skipped with a notice. The framework declares the `theme` setting (`ThemeSetting`; choices: the built-ins, then themes.json's) unless the app declared one (`Config.FrameworkTheme()`), and the Model applies it. `Runtime.ReloadThemes`, `Config.Schemes`, verbs `themes.reload`, `themes.path`, `themes.list`. `Appearance.Accent` still goes on top; mono and `NO_COLOR` stay colourless.
- o-story: a story's `themes` field; stories `chrome/scheme-light`, `scheme-user`, `scheme-user-accent`, `scheme-malformed`.

### Catalog pages, widgets and the target resolver (`feat/catalog-pages`)

- Data pages: `cli.CatalogPage` gains `layout` (`stack`, `split`, `groups`), `lists` (`{id, noun, source, title}`) and `detail` (`{title, fields}`). An extension declares one with `cli.DeclarePage(r, p)` and `cli.Catalog` publishes it whole; a Go-drawn page stays `{id, title}`.
- A host builds it with no Go code of the extension's: `cli.MountPage(m, doc, p, cli.PageConfig{Noun, Fetch})` / `cli.MountPages(m, doc, cfg)` return a `*cli.PageView` (`ListsRender`, `Reload`, `SetRows`, `SetState`, `SetError`, `SetStatus`, `Row`, `List`). Loads are quiet `catalog-load` jobs; rows are `<list>/<row id>` instances of the host's noun with `Data` the row's id. `cli.DecodeRows` reads a list answer (array or JSON Lines). This is nabe's hand-built mount page as framework code.
- Widgets: `pages[].widgets` (`cli.CatalogWidget{id, kind, title, source, fields, columns, rows}`), drawn by the framework above a data page's lists: `kv` (a key/value panel), `status` (a line with a progress bar and state), `table` (columns over cells or fields, capped rows). Data from the widget's `source` on `Reload` or `PageView.SetWidget`. The plan's reserved top-level `widgets` lives on the page it draws on.
- `Runtime.ResolveTarget func(target string) (string, error)` and `Runtime.TargetInstance(target)`: a request whose target is not an instance asks the resolver for the instance standing for it before `ExecuteAt` refuses it (`unknown target`), so a foreign id reaches its row from keys, the palette, the CLI and the API; a resolver error is the refusal, `target "X": …`. A confirm stores the resolved target. `cli.Shell.Reveal` now runs only for a target the runtime cannot resolve yet, and the resolver maps it after Reveal loaded the rows.
- o-story: a page with `catalog` is a mounted data page over canned `answers`; stories `catalog/*`.

### Also since v0.1.1

- Framework `bindings list --all` lists every stored noun and instance binding table as configuration JSON, including inactive modes and contexts. The default listing remains focus- and mode-specific. The CSV example now exposes framework operations through `csv NOUN VERB`, including `csv bindings list --all`; the socket CLI also accepts `--all`.
- Keyboard help shows bold, underlined binding-owner groups from inner to outer, with movement last. Scrolling within a group keeps its owner heading visible, even when its bindings invoke another noun's operations.

## v0.1.1 (2026-10-25)

Requires oden v0.1.1. Fixes from mtm's test pass:

- `Tree.Record(TreeAction{ID, Label, Undo, Redo})`: an application change kept outside the nodes (a task status) goes on an outline's undo stack in order with the tree's edits. Story `tree/undo-app-action`.
- The footer shows only the newest notice, cut to half the width with `(+N more)`, so notices never hide the hints. Story `notices/footer-keeps-hints`.
- An argument error (`ArgumentError`, `Response.Argument`) adds no `pass --target, one of: …` hint in the CLI.
- `?` help: a row's `Help` replaces its operation's description (the `"`, `q`, `@` and count rows now say what they do); a generated prefix cancel (`d esc`) is listed only while a sequence on its prefix answers.

## v0.1.0 (2026-10-25)

First tagged release. Requires Go 1.26 and oden v0.1.0.

- Bubble Tea v2 application framework: retained pages, nouns and instances, one focus field and one global mode, one stack walk for actions and bindings, binding rows (`Define`, bindings files, capture rows, verb guards), `ValidateBindings`.
- Components: lists and tables (lists with columns), the tree and outline editor (`AddTree`), modal text inputs with an undo tree, registers and macros, the file picker, terminal instances, partial-screen modals and confirm prompts.
- Chrome: the ex-mode command line and palette with parameter choices, footer hints as `key noun.verb`, `?` bindings help, a notice line and the two-row jobs ticker.
- Runtime: operations with a delivery contract for off-loop jobs, action history with dot-repeat, tree queries, and live control over a Unix socket.
- `cli`: the generic NOUN VERB shell, the catalog answer and `cli.Mount` into oden command groups.
- `story` and `o-story`: stories as data played headless against the real chrome, and session recordings.
