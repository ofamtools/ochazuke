# Changelog

Generated by o-inventory from the snapshots in ~/hub/inventory: one entry per snapshot, newest first, only the concepts that changed. Every line but Commits is derived from the diff; `fixed:` lines quote `fix:` commit subjects.

## Unreleased

### Configuration

- `config.reload` (`Runtime.ReloadConfig() ([]string, error)`): one verb reads every config file again, in dependency order: `themes.json` (so the `theme` setting's choices are current), `settings.json` (observers fire; the Model applies the theme), `actions.json`, `bindings.json` (applied once; a row can name an action's verb), each only when the app uses it, then the app's own files. A bad file or entry is skipped and is a notice; each file's previous notices are withdrawn first. The result is every problem (`problem[]`), each naming its file; an error without a config directory. A fetch with no default key; in the palette, `operations.list`, the catalog (builtin) and the CLI (`BIN config reload`).
- `Runtime.OnConfigReload(name, fn func() []string)`: an application joins `config.reload` with its own files (run after the framework's, in registration order); problems get the `name: ` prefix unless they carry it, are notices and are withdrawn at the next reload.

### Help

- `?` help has three views, `S` (`bindings-help.view`) cycling them: **here** (unchanged: what the focus answers now), **pick** (the same table for a chosen noun and mode, as if the focus were there: `n` `bindings-help.noun` and `m` `bindings-help.mode` open choosers of every noun and of the modes; the header reads `noun: X · mode: Y`) and **table** (a noun's keys by mode: a row per key or key class, a column per mode whose own table has rows for the noun or app, each cell the operation that answers, `.verb` for the noun's own, `(op)` when app answers, `op?` when guarded; `z l`/`z h`/`$` scroll the modes with the key column kept; the selected key's rows per mode, arguments, guard and answering level under the table). The title names the view (`Keys · pick`); the rows are hinted (`S view`, `n noun`, `m mode`) and guarded to the views they act in. `NounHelp(r, noun, mode)`, `Runtime.HelpTable(noun, pending)`, `Runtime.HelpModes(noun, pending)`.
- The hypothetical walk shares the live one's code: `walkOf` (the capture pass) and `scanRows` (first row per key, mode table before any-mode table, exclusive pending modes, prefixes) serve both `levelRows` and `nounRows`; a guarded row is kept with its guard (`HelpRow.Guard`), and the rows answering when it is false follow it. Stories `help/pick-view`, `help/table-view-120`, `help/table-view-80`, `help/settings-*`.
- Settings (section help, declared by `EnsureConfigSettings`): `help.pick-view` and `help.table-view` (booleans, default true: the view is in `S`'s cycle; with both off `S` is not offered) and `help.pending-modes` (default false: pending modes and key-sequence prefixes as pick's modes, pending modes as table columns).

## v0.14.0 (2026-10-27)

Modals take about 80% of the width with no 78-column cap and choosers fill it; terminal overlays let an app label a live pane (hints) with the new `upper` and `ctrl+alpha` key classes and the `letter` source; a parameter's `Noun` lists that noun's things as its choices.

### Modals

- A modal's width is about 80% of the terminal columns with no 78-cell cap (`ModalSize`, `ComposeModal`, `ComposeModalBlock` unchanged in signature); content-sized modals only widen when their content is longer. A chooser fills the modal's width: its search line and rows are padded to it, so the panel does not resize while typing, and column fitting and the preview split use it. Story `chooser/wide-fills`.

### Terminal

- `Terminal.SetOverlay(*TerminalOverlay)` / `Overlay()`: an application draws over a terminal's live frame without touching it. `TerminalOverlay{Dim, Marks}` fades the pane (the `modal-dim` backdrop style; faint in mono and NO_COLOR) and draws each `OverlayMark{Row, Col, Text, Style}` over the cells from its pane cell, cut at the edge, wide-rune and style aware (the empty style draws reverse and bold). A new frame keeps the overlay; nil clears it; `Frame()` and the stream never see it.
- Hints over a live pane need no new mode machinery: an application base mode made passthrough (`DefineMode(name, false)`, `DefinePassthrough`) entered by a verb a `leader_pending` row runs (`SetMode`), whose rows on the terminal noun take every key, so nothing reaches the pane; leaving is `SetMode("terminal")`. Recipe in AGENTS.md's terminal row; stories `terminal/hints-*`.

### Keys

- Key classes `upper` (`Upper`: one uppercase letter, answers before `alpha`) and `ctrl+alpha` (`CtrlAlpha`: ctrl+a to ctrl+z, exclusions spelled in full, `ctrl+alpha-ctrl+h-ctrl+m`), and the argument source `letter` (`SourceLetter`: the key's letter lowercased without ctrl+/shift+, so `f`, `F` and `ctrl+f` all read `f`). Legacy terminals send ctrl+h/i/j/m as backspace/tab/enter and ctrl+[ as esc: labels read through `ctrl+alpha` should avoid h, i, j and m.

### Palette

- `Parameter.Noun` (`noun` in the catalog): the value names one of the noun's things, so the palette and CLI help list the rows of `NOUN.list` (a read with no required parameter; `Runtime.ChoicesSource`, published as the catalog's `source`) or else the noun's live instances, list rows included (every row, in list order). `ParseChoices` reads a map row's id from `id`, `key` or `name` and its label from `label` or `title`, and `[]Operation` as `noun.verb`. `page.open`, `mode.set`, `mode.enter`, `confirm.set`, `list.focus`, `input.focus` and `modal.push` name their nouns. Story `palette/noun-choices`.

## v0.13.0 (2026-10-26)

Table cell mode is opt-in: CellSelect(); every other table selects rows as before v0.12.0.

Table cell mode is opt-in: only a table added with `CellSelect()` is cell-based.

### Tables

- `CellSelect()` (an `InstanceOption` for `AddList`) makes a table cell-based: the current column, `h`/`l`, `0`/`^`/`home`, `$`/`end`, `N|`, `g c`, `y` (copy the cell) and `z >`/`z <`/`z =`, with the column and widths remembered in `tables.json`, as `v0.12.0` gave every table. `AddTree` ignores it.
- Every other table selects rows again, as on `v0.11.0`: `h`/`l` are free for row nouns, `$`, `^` and `0` (without a count) run `list.scroll-columns` (verb guard `table-scrolls`), `z l`/`z h` scroll a column, no current cell is drawn, and nothing is read from or written to `tables.json` for it (widths a `v0.12.0` cell table saved no longer stick to it). Story `tables/row-select`.
- `RowSelect()` is a deprecated no-op; the framework's trees, `?` help modal and Settings page no longer pass it.
- `Y` (copy the row's cells joined by tabs) answers on every table (verb guard `list-table`), `y` only on a cell-mode table.
- `V` answers on every table with marks: a visual range over the marks, cell-mode or not. `esc` ends it through `list.end-visual` (verb and row guard `list-visual`), so the row no longer hides an outer `esc` hint, such as a modal's `esc modal.pop`, over a table.
- The width keys `z >`/`z <`/`z =` need a current column, so they answer on cell-mode tables only; `List.SetColumnWidth` still sets a width on any table.
- `list.column`, `list.choose-column` and `list.resize-column` refuse a row-select table ("not a cell table"); `list.yank {what: cell}` too.
- cli: catalog tables select rows, so the groups rail's `h` back row (guard `list-first-column`) answers at once on them. Story `catalog/groups-table-h`.

### o-story

- A story list takes `cellSelect` (`ListSpec.CellSelect`); the cell stories set it, and the goldens of tables that select rows read `R|` again.

## v0.12.0 (2026-10-26)

Tables are cell-based: a current column, per-column widths, and V for rows.

Tables are cell-based, like o-csv's grid: a current column, column widths, and a visual row selection.

### Tables

- A list with columns has a current column (`List.Column`, `SetColumn`; `column` in its state). On the `list` noun in normal mode, on a cell-mode table only: `h`/`l`/`left`/`right` move by column (counts), `0`/`^`/`home` and `$`/`end` go to the first and last, `N|` to column N, `g c` chooses one from a chooser of the titles (`list.column`, `list.choose-column`, motions); `j`/`k` keep the column. Every frame scrolls the column offset as little as shows the current column; `z l`/`z h` carry it along. `$`, `^` and `0` no longer run `list.scroll-columns`; `list.column` scrolls a row-select table the same way. Stories `tables/cell-motion`, `tables/column-count`.
- The current cell is drawn reverse and underlined inside the row's highlight, the header underlines the current column's title, and an unfocused table fades both. Story `tables/unfocused-cell-dimmed`.
- `y` and `Y` copy the current cell, or the row's cells joined by tabs, into the registers (`list.yank {what, register}`).
- `z >`/`z <` widen or narrow the current column by `ColumnWidthStep` (2) cells, never below 3; `z =` makes every column automatic (`list.resize-column`, `list.reset-columns`; `List.SetColumnWidth`, `ColumnWidths`, `ResetColumnWidths`). The widths and the current column are remembered per table id in the state directory's `tables.json` (`Runtime.TableState`, `SetTableState`). Story `tables/column-resize`.
- `V` starts a visual row selection drawn into the marks: `j`/`k` extend it (they clamp), a row's application verb runs for every selected row through `list.apply`, `esc` or `V` ends it and the marks go back (`list.visual`, `List.Visual`, `StartVisual`, `EndVisual`). Story `tables/visual-apply`.
- `list.apply` takes `args` for every row's request, and a verb with a confirm asks once for all the rows.
- `RowSelect()` keeps a table on row selection: trees' lists (h/l expand and collapse), the `?` help modal and the Settings page use it.
- y, Y, V and the width keys are hidden from the footer; `?` help lists them.
- cli: the groups rail's `h`/`left` back rows take the new guard `list-first-column`, so in a table `h` moves left and goes back to the rail from the first column. Story `catalog/groups-table-h`.

### grid

- Per-column widths: `z >`/`z <`/`z =` on the grid noun (`grid.resize-column`, `grid.reset-columns`; `Grid.SetColumnWidth`, `ColumnWidth`, `ColumnWidths`, `ResetColumnWidths`). A given width replaces `MaxCellWidth` for its column and is remembered under the grid's id.

### o-story

- Goldens read `C|` (`c|` dimmed) for a highlighted row that holds a table's current cell; the expect field `cell` names the current cell's text.

## v0.11.0 (2026-10-26)

The terminal leader can wait for the next key indefinitely.

- `terminal-leader-timeout` (`TerminalLeaderTimeoutSetting`, duration): how long `leader_pending` waits for the next key before it sends the leader alone. `0` never expires, so the leader waits like tmux's prefix; a positive value is the leader's own timeout. `EnsureTerminalLeader` declares it beside `terminal-leader` unless the app declared it first (with its own default); the framework default is `DefaultBindingTimeout`, and until settings.json holds a value the leader follows `BindingTimeout`. Other key sequences keep `BindingTimeout`. Story `terminal/leader-timeout-zero-waits`.

## v0.10.0 (2026-10-26)

An unfocused list keeps its selected row, faded; the dims are settings. A list can clear its filter when enter picks a row.

### Unfocused lists and dims

- A page list without the focus keeps its selected row in reverse video and is drawn faded as a whole, so the row an unfocused list is on (a tree beside a live terminal) stays visible and the focused row is the one highlight at full strength. A list in a modal stays plain until focused; a tree editing a line is not faded. Replaces the old rule "an unfocused list draws every row plain" (UX rule R5.1). Stories `lists/unfocused-dimmed`, `lists/beside-terminal-keeps-row`.
- Two framework settings, declared by `EnsureConfigSettings`: `dim-unfocused` (percent an unfocused list fades toward the background, default 20) and `modal-dim` (the page behind a modal, default 35, the backdrop's look until now). Both 0 to 90 (`MaxDim`); 0 is off.
- `Styles.Fade(percent)` blends the scheme's text colour toward its surface (`lipgloss.Blend1D`, perceptual); in mono or NO_COLOR any fade is the faint attribute. `Styles.WithDims(modal, unfocused)` sets the new `Styles.Backdrop` and `Styles.Unfocused`; `Model.Styles()` applies the settings. `NewStyles` uses the defaults.
- o-story: `highlighted` counts full-strength highlights only; the new `dimmed` counts highlights under faint; goldens mark a dimmed-only row `r|`.

### Lists

- `ClearFilterOnEnter()` (an `InstanceOption` for `AddList` and `AddTree`): enter in the list's filter line chooses the selected match (`list.filter-choose`, guard `list-chooses`): the filter clears, the selection stays on that row and on screen, the mode is normal. With no match enter keeps the filter, as on every list; other lists are unchanged. Story `lists/filter-enter-clears`.

### Fixes

- Custom components' explicit `Block.Cursor` now reaches `Model.View().Cursor` without a focused input, using the normal block or visual underline shape. Blocks without a cursor remain hidden; input and terminal cursor shapes are unchanged.

## v0.9.0 (2026-10-26)

### List motions

- Every list answers Vim's paging motions in normal mode: `g g` and `G` go to the first and last row, and with a count to that row (`5G`, `5gg`, `list.goto {position, row}`); `ctrl+d`/`ctrl+u` move half a page (a count is rows) and `ctrl+f`/`ctrl+b` a page (a count is pages) (`list.scroll {delta, half, steps}`). A page is the list's own window, else the page body's height; the window moves with the selection. They clamp at the list's edges, never spill, and are motions (off the footer, under `movement` in `?`). A row noun that binds the same key keeps it. Story `lists/page-motions`.
- A table with more columns than fit scrolls them (`list.scroll-columns {to, delta, steps}`, `List.ColumnOffset`): `$` brings the last column into view, `^` (and `0` without a count) goes back, `z l`/`z h` move one column. The first column stays; the unscrolled view still drops columns by `Priority`. The keys answer only on a table that hides a column or is scrolled. Story `tables/column-motions`.
- A key-sequence prefix whose only remaining row is its generated `<prefix> esc` cancel (every sequence on it guarded off) no longer waits for a second key.

## v0.8.0 (2026-10-26)

The Settings page is redesigned after tuios's: a list of fields, not a table.

A state verb answers what changed since the host's last poll instead of every row, and the catalog tells a tool's own verbs from the framework's. Every list filters with `/`, and an Update no longer visits list rows.

### Settings page

- Sections are tabs across the top instead of a rail, so the rows get the whole width. `tab` and `]` show the next section, `shift+tab` and `[` the previous, wrapping (`settings.section {step}`, or `{name}`); each section keeps its selected row. With one section there is no tab row.
- One row per setting: its name on the left, its value on the right. There is no header and no Value/Default/Source columns. A `•` after the name marks a value that is not the default. `‹ value ›` marks a value `h`/`l` steps.
- The description under the rows says what the default is and where the value comes from: not in settings.json, set in settings.json, or settings.json holds an invalid value (with the reason) so the default applies.
- List settings: a list setting's row shows its item count (`(none)` when empty), and each item is a row directly beneath it with the name column blank. On a list's row `enter` or `n` adds an item at the end. On an item row `enter` or `i` edits it, `n` adds one after it, `d d` deletes it and `r` resets the whole list. An empty item is refused.
- `u` (or `ctrl+z`) takes back the last change made on the page and shows its row. A value that was invalid in settings.json comes back as it was. `u` is offered only when there is a change to take back.
- `backspace` and `delete` reset a setting, as `r` does.
- The page reopens on the section and row it was left on.

### State cache and deltas

- A state verb run through `cli.Shell` takes `--since LIST=HASH,...` and `--since-cache ID` (`cli.StateFlags`, `FormatSince`/`ParseSince`; `--since=` asks for every list in full, with hashes) and answers JSON Lines: a header `{"state":1,"cache":ID}`, then per list `unchanged`, a `delta` (the changed and added rows whole at their indexes, the removed ids) or the list in `full`, each with its content hash (`RecordHash`, `ListHash`). An unknown hash, another cache id or a pruned version answers full, never wrong. The catalog declares `stateDelta: 1`.
- The extension side caches each list's last versions (`Shell.StateCache`): `(id, record hash)` files under `$XDG_CACHE_HOME/<bin>/state/<scope>/lists/<list>/`, written temp + rename and content-addressed, `Keep` (2) versions per list and `Scopes` (8) scopes, the rest deleted. `StateCache.Scope(args)` adds to the scope (a TUIOS server); `StateCache.Fingerprint(args)` (`StatFingerprint(paths...)`) answers an unchanged poll without running the verb, except under `--fresh`; `StateCache.Off` turns it all off.
- `MountPage` uses it: with `PageConfig.FetchFlags` a page's `Reload` sends its list hashes and applies the answer (`PageView.ApplyState`): unchanged touches nothing and skips `OnRows`, a delta goes through `List.Patch`, full through `SetRows`; a list whose hash does not match after applying is fetched again in full, once. `PageView.Refresh` forgets the hashes. An older extension (no `stateDelta`) keeps full answers through `Fetch`.
- `List.Patch(ListPatch{Upsert, At, Remove})` (and `PatchItems`) is `SetItems` over the patched rows: kept rows keep their instances, selection and marks, and only removed rows close. `SetItems` keeps a table's measured widths when every row draws the same cells.
- `cli.DecodeState` and `RowReader.Answer()` read a delta answer. Benchmarks `BenchmarkStatePoll` and `BenchmarkStateApply` cover an 8,000-row poll, unchanged and with one row changed.

### Builtin verbs

- Every ochazuke tool's catalog lists the framework's verbs beside the tool's, and some are application verbs (the outline's 14, the chooser's 3), so hosts mounted them as the tool's (`ai-outline`, `qbt-outline`). `Operation.Builtin` now marks every operation the framework registers: everything `NewRuntime` and `NewModel` register, and what a framework constructor registers later (`NewPicker`, `NewPalette`, `NewAppearance`, `grid.Register`, `markdown.Register`, `cli.AddCommands`). An application's verb is never builtin, even on a framework noun (`history.capture-hook`).
- The catalog's verbs carry `builtin` (`cli.CatalogVerb.Builtin`). `CatalogDoc.AppNouns()` is what a host mounting a tool's verbs mounts: each noun with only its non-builtin verbs (`CatalogNoun.AppVerbs()`), nouns left with none dropped. A `MountPage` list of a noun's verbs lists only the tool's.

### Every list filters

- `/` on a focused list (page lists, tables, catalog lists, the Settings page's section, a list in a modal) opens a query line above the rows; typing keeps the rows whose label or cells hold every word, ignoring case, in list order, `N of M` on the right. In the `list_filter` mode up/down and `ctrl+n`/`ctrl+p` move among the matches (no spill), enter keeps the filter (`/` edits it, `esc` clears it), esc clears it and selects the row `/` found, backspace on an empty query leaves, `ctrl+u` empties it.
- Rows are hidden, never removed: `SetItems` and `Patch` filter the new rows and keep the selection by id, marks survive, `list.apply` acts on the marked rows shown, focus landing on a hidden row clears the filter.
- An application's own `/` wins at any level: the framework's is an `app` row (guard `list-filterable`), its `/ filter` hint last on the footer.

### Faster updates

- `Runtime.components()` (every `Deliver` and `PendingCommands`) walks an index of the instances that are not list rows instead of sorting every instance, and the list verbs no longer copy every row into their result. `BenchmarkUpdateKey` at 16,000 rows: 818 µs to 11 µs a key; nabe's ai page 295 µs to 32 µs.

### API changes

- `SettingList` (`"list"`): a setting whose value is `[]string`. settings.json keeps it as a JSON array, `settings set NAME '["a","b"]'` sets it, and `Settings.Strings(name)` reads a copy. A value of another shape is refused, as are an `Enum` and a default that is not a list of strings.
- `settings.section {step, name}` and `settings.undo`. The nouns are `setting-item` (`edit`, `add`, `delete`, `reset`) and `setting.add`. The guards are `setting-list` and `settings-undo`.
- A table whose columns have no titles draws no header (`List.View`).
- The page's lists are `__settings/list[/SECTION]` (were `__settings/table[/SECTION]`); the `__settings/sections` rail and the `settings-section` noun are gone. Item rows are `__settings/item/NAME/INDEX`.

- `Operation.Builtin`, `Runtime.Builtin(register func())` (marks the operations `register` added; for framework packages), `cli.CatalogVerb.Builtin`, `CatalogDoc.AppNouns()`, `CatalogNoun.AppVerbs()`.
- `list filter --target LIST --query Q` (empty clears), `list.filter-open|type|erase|keep|clear`, `list.move {clamp}`; `List.SetFilter`, `Filter`, `Filtering`, `Shown`, `Height` (`Len` plus the query line); `ListFilterMode`. `Items`/`Len` stay every row; a filtered list's state has `filter` and `total` and its `items` are the rows shown.
- `cli.StateDeltaVersion`, `StateFlags`, `FormatSince`, `ParseSince`, `StateList`, `RecordHash`, `ListHash`, `StateCache`, `StatFingerprint`, `DecodeState`, `RowReader.Answer()`, `PageConfig.FetchFlags`, `PageView.ApplyState`, `PageView.Refresh`, `PageView.SinceFlags()`; `ochazuke.ListPatch`, `List.Patch`, `PatchItems`.

### Migrating

- Stories or tests that read the old columns (`Setting`, `Value`, `Default`, `Source`) or the rail (`Sections`, `__settings/section…`) read the tabs, the rows and the description instead.
- A host that mounts another tool's catalog verbs (nabe, mtm) mounts `doc.AppNouns()` instead of comparing keys against a fresh `NewRuntime()`+`NewModel()`. A catalog from a tool built before this release has no `builtin`, so every verb reads as the tool's; keep the old check as a fallback until the tools are rebuilt.

## v0.7.0 (2026-10-26)

A Settings page instead of the settings modal, one action history whose entries are small and typed, and two per-key costs that grew with the rows gone: `j` on an 8,000-row list in nabe's ai page went from about 3.7 ms to 2.4 ms a key (the keypress itself from 1.4 ms to 0.3 ms), and `BenchmarkPageFrame` at 8,000 rows from 2.1 ms to 0.6 ms.

### Settings page

- Settings get a page of their own instead of the cramped modal. `settings.edit` opens (or switches to) the framework's Settings page: a rail of sections on the left (the settings without a section first, as General, then each section in declaration order), the section's table on the right (setting, value, default, source: `default`, `settings.json`, or `default (file value invalid)`), and below it a detail of the selected setting (description, type, allowed values; `J`/`K` scroll it, `>`/`<` move the divider). Editing is as before: every change is saved as it is made, `enter` flips or steps or opens the value prompt, `h`/`l`/`space` step, `r` resets. `q` or `esc` (`settings.close`) goes back to the page it was opened from with its focus and mode. The page is registered when it opens and removed when it closes, so it is a tab only while open.

### History

- Every history entry has a `kind`: `action` (the user's interaction: motions, focus, page and modal moves, modes, the palette's own keys), `change` (edits and verbs that change something; dot-repeat reads only these) or `fetch` (state, list and show verbs, reloads, a verb declaring `Rows` or `State`, a host calling an extension). `system` is reserved for what the runtime does on its own; nothing records it yet.
- The kind comes from the operation (`Operation.HistoryKindOf`): `Operation.HistoryKind` when set, else `fetch` for `Rows`/`State`, `change` for `Repeatable`, `action` for `Motion`, `change` for any other application verb (an extension verb that declares nothing is kept with the user's entries), `action` for any other interaction verb. The framework's reads and reloads (`state.get`, `history.list`, `jobs.list`, `bindings.list`, `operations.list`, `settings.list`, `*.reload`, ...) are fetches; its interaction verbs that change a setting, a register or a pane (`settings.set`, `input.undo`, `register.set`, `terminal.send`, ...) are changes.
- `history.list {last, kind}` and `state get /history` show actions and changes by default; `kind` takes a comma list or `all`. `history.list` and `state.get` are now recorded, as fetches.
- Fetches the user did not type into the palette keep their own ring, the last `HistoryFetchLimit` (100), so a host polling a state verb never pushes the user's entries out of the `history-limit` ring. A fetch typed into the palette stays with the user's entries, and palette Up/Down recalls it.
- `history.jsonl` keeps fetches only while the new `history-fetches` setting is on (default off: a poller would fill the file, and nothing reads a fetch back after a restart). Lines from older files get their kind when they are read.
- An entry never holds the value its operation returned: `j` over a list encoded the list's snapshot into the ring on every key (about 1 ms at 8,000 rows). A request that moved the focus, page or mode records `moved {from, to}` (`HistoryMove`, `HistoryPlace`: ids, the page and the mode), so `j` is "row A to row B".
- `PageList` reads app's page order (kept by `RegisterPage` on the app instance, ordered as `Children("app")` is) instead of scanning every instance; it runs about three times a frame. `BenchmarkPageList` is flat in the row count.

### API changes

- `HistoryEntry.Kind`, `HistoryEntry.Moved`; `HistoryMove`, `HistoryPlace`; `HistoryResult.Value` is gone (nothing read it; the file already dropped it). A reference to a response (a hash into a content-addressed store) would go in `HistoryResult` beside `ok`.
- `Operation.HistoryKind`, `Operation.HistoryKindOf()`, `NounBuilder.Fetch()`; constants `HistoryAction`, `HistoryChange`, `HistoryFetch`, `HistorySystem`, `HistoryFetchLimit`, `HistoryFetchesSetting`.
- `Runtime.HistoryOf(n, kinds...)`; `Runtime.History(n)` returns every kind.
- The catalog's verbs carry `history` (`cli.CatalogVerb.History`, the verb's `HistoryKindOf`), and actions.json entries take `history` (`Action.History`: `action`, `change` or `fetch`).
- `Setting.Section` (JSON `section`) files a setting under a section of the Settings page; without it the section is the name before its last dot (`ext.ai.poll-every` is in `ext.ai`), `Setting.SectionName()`.
- `settings.close`; `Runtime.AddSettingsPage()` registers the Settings page as a permanent tab; `SettingsPageID` (`__settings`), `SettingsGeneral`.
- The `settings-editor` modal and its `ModalView` are gone; the value prompt (`setting-prompt`) stays. Row ids are `__settings/row/NAME` (were `__settings/NAME`). The `l`, `right`, `space` and `left` step rows are `Hide`, so the footer shows one `h/l setting.cycle`.

### Migrating

- A host that mounts another CLI's catalog verbs (nabe) should copy each verb's `history` to its operation (`Operation.HistoryKind`, or `NounBuilder.Fetch()` for `fetch`), so the extension's fetches stay out of the user's history there too; without it a mounted verb records as a change.
- An application verb that only reads should call `.Fetch()` (or declare `Rows`/`State`).
- Code that read `HistoryResult.Value` reads the operation's return value instead.
- An application that binds `settings.edit` keeps its key; it now opens the page. Code or stories that expected `TopModal() == "settings-editor"` check `Runtime.Page == SettingsPageID` instead. With no page of its own to go back to, `settings.close` refuses.

## v0.6.1 (2026-10-26)

A patch release: a page with many rows no longer lags on every key.

### Fixed

## v0.6.0 (2026-10-26)

### Highlights

- `config export [DIR]` writes a complete reference of an application's user configuration, by default into `<config dir>/reference/`: `settings.json` (every declared setting at its current value), `settings.reference.json` (type, default, enum, description and value per setting), `bindings.reference.json` (every key row, `bindings list --all`), `actions.example.json` and `themes.example.json` (every field, valid as they are) and a `README.md` explaining each file, where the live files are, and that copying defaults pins them. Files are written atomically; the live config files are never written without `--force`.
- `config path` prints the config, state and default reference directories.
- A binding row's guard is part of its identity: identity is the noun or instance, the mode, the keys or pattern, and `when`. A row with `when: X` replaces only the row with the same keys and guard `X`; a row without `when` replaces only the unguarded one; an unbind (`"request": null`) removes only the row with its own `when`. This holds for `Runtime.Bind`, the builder (`Bind`, `Pattern`, `When`, `Unbind`), `bindings.load`, the user `bindings.json` and `bindings.reload`'s undo, so a guarded row and its fallback on the same keys can be overridden or unbound one at a time, and `config export`'s `bindings.reference.json` loads back exactly. A replaced row keeps its place in the table (it used to move to the end), a new guarded row goes before the unguarded row on its keys so it answers while its guard holds, and reload puts a replaced row back where it stood. The `input` guard the framework puts on the editor's `input.*` rows (`ImplicitGuard`) is not part of the identity: a row without `when` replaces or unbinds those defaults as before, and a user row running an `input.*` operation on the editor noun gets the guard too.
- The user `bindings.json` loader reports a row that a guarded default on its keys still answers before, as a notice (`bindings.json: row N KEYS: the default NOUN.VERB row (when "G") answers first while its guard holds; to replace it, add "when": "G"`): an added row behind a guarded row, any row behind a guarded capture row on its keys (`ctrl+c` and its `no-modal` capture row), and an unbind without `when` that leaves a guarded row in place.

### API changes

- `ModeBuilder.UnbindGuarded(keysOrPattern, guard)` removes the row with that guard; `ModeBuilder.Unbind` now removes only the unguarded row. `ModeBuilder.When` after `Bind` re-places the row under its guard (an unguarded row it replaced comes back).
- `Runtime.ExportConfig(dir, force) (ConfigExport, error)`, `ConfigExport{Dir, Files, Config, State}`; `Config.Paths() ConfigPaths`, `ConfigPaths{Config, State, Reference}`.
- The `config` noun: `config.export {dir, force}` (`dir` positional), `config.path`.
- Constants `ReferenceDir`, `ReferenceReadme`, `SettingsReferenceFile`, `BindingsReferenceFile`, `ActionsExampleFile`, `ThemesExampleFile`.

### Migrating

- An unguarded row no longer replaces or unbinds a guarded row with the same keys; it adds an unguarded row beside it (which answers only where the guarded row's guard is false), and the loader says so in a notice. To replace or unbind a guarded default, give the row the default's `when` (`bindings list --all` and `bindings.reference.json` show it). The editor's implicit `input` guard is the exception: `{"noun": "editor", "mode": "normal", "keys": "x", "request": null}` still unbinds `x`. The defaults with a guard of their own are few: `0` in `operator_pending` (`when: count`), the `ctrl+c` capture row (`when: no-modal`), and the rows an application guards. The same goes for code: `Bind("k", row)` without a guard leaves a guarded `k` in place, and `Unbind("k")` leaves it too (use `UnbindGuarded("k", guard)`).
- An application that defined its own `config` noun with an `export` or `path` verb now collides with the framework's (`Register` panics on a duplicate operation); rename its verb.

## v0.5.0 (2026-10-26)

A minor release: inline completion for inputs, a preserved-newlines option for Markdown, and `Runtime.Bind` no longer cancels a key sequence it does not touch.

### Highlights

- Inline completion: an application gives an input triggers such as `@`, `$` or `[[`, each with an asynchronous search. Typing a trigger at the start of a token offers the search's suggestions for the rest of the token in a list drawn under it, while typing keeps editing the same input.
- The token runs from the trigger to the next whitespace (`/` never splits it); the query is the whole token after the trigger, wherever the cursor is inside it. Of overlapping triggers (`[` and `[[`) the longest wins.
- Accepting replaces the whole token and keeps the trigger (`@src/ma` becomes `@src/main.go`) as one undoable edit.
- Searches run off the loop after a 150 ms pause in typing. An answer to a request older than the one on screen is dropped, so a slow, late answer never replaces a newer one; a search error is shown in the list.
- Keys while the list is open: `ctrl+n`/`ctrl+p` or `down`/`up` move, `tab` takes the highlighted suggestion (else the first), `enter` takes it only once one is highlighted (so enter after a typed token still submits or breaks the line), `esc` hides the list and stays in insert. `tab` on a token with the list closed opens it at once, unless the application binds `tab` itself.
- The demo's notes field completes `@` library entries, `$` skills and `[[` pages. o-story stories `completion/*` (typing-opens, look, accept-undo, escape-stays-insert, error-row, mid-token-tab, longest-trigger); a story input takes `completions: [{trigger, items, fail}]`.
- Markdown keeps line breaks on request: `markdown.PreserveNewlines()` makes every newline inside a paragraph a line break (Glamour's `WithPreservedNewLines`), for notes written as plain lines. Long lines still wrap; code blocks and tables draw the same. A Doc with the option keeps its items, highlight and byte-exact toggles. o-story stories `markdown/preserve-newlines` and `markdown/render-preserve-80`.
- `Runtime.Bind` and the builder's `Define(noun).Mode(m).Bind` while a key sequence is pending (`d` of `d d`) keep the sequence unless a row they add or replace is on it: in its mode, with keys equal to, extending or extended by the keys typed so far. Before, any new row cancelled it, so an application binding rows mid-sequence broke `d d`.

### API changes

- `Completions(triggers...)` (an `InstanceOption` read by `AddInput`) and `NounBuilder.Completions(triggers...)`; `Input.Completions`; `Runtime.CompletionTriggers(id)` (the input's own, else its noun's). A trigger must be non-empty, hold no whitespace and have a search.
- `CompletionTrigger{Trigger, Search}`, `CompletionSearch func(ctx, query) ([]Suggestion, error)`, `Suggestion{Text, Label, Detail}`, `SearchStrings(func(ctx, query) ([]string, error))`.
- `FindCompletionToken(text, cursor, triggers) (CompletionToken, int, bool)` and `CompletionToken{Start, End, Trigger, Query}`.
- `Runtime.Completer() *Completer`: `Open`, `Input`, `Token`, `Suggestions`, `Err`, `Highlighted`, `Searching`, `State`, `Debounce`, `DebounceTick`, `DebounceCurrent`; `CompletionDebounceMsg{Seq}`, `DefaultCompletionDebounce`, `CompletionNoun`.
- The `completion` noun: `completion.open` (guard `completion-available`), `completion.move {delta}` (a motion), `completion.accept`, `completion.dismiss`; rows in insert mode on the noun (`esc`, `tab`, `enter`, `ctrl+n`, `ctrl+p`, `down`, `up`) and `tab` → `completion.open` on the editor noun. Guards `completion-rows` and `completion-highlighted`.
- The stack walk reads a focused instance's inner level first (the open suggestion list); nothing else sets one.
- `markdown.Option` and `markdown.PreserveNewlines()`; `markdown.Block(text, width, appearance, opts...)` and `markdown.New(r, id, parent, src, opts...)` take options (existing calls compile unchanged). Renderings are cached per option. A story's markdown spec takes `preserveNewlines`.

### Migrating

- The Markdown option needs no change. An application that relied on `Bind` clearing a pending sequence after binding an unrelated row now keeps the sequence; one that binds a row on the sequence still has it cancelled.
- Completion needs no change: `tab` in insert mode on an input with no triggers is unchanged (the new editor row's verb is guarded off there). An application that binds `tab`, `enter`, `esc`, `up`/`down` or `ctrl+n`/`ctrl+p` on an input with triggers keeps them while the list is closed; while it is open the list's rows answer first.
