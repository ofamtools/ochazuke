## v0.17.0 (2026-10-27)

The framework namespace is `ochazuke` (was `app` in v0.16.0, which collided with the `app` noun's own verbs); `app.<framework noun>` stays a silent alias for one release. `cli.ExtensionNamespace` strips `o-` (o-ai → `ai`). The catalog lists each noun once. New card timeline component (`AddTimeline`).

### Framework namespace `ochazuke`

The framework namespace is `ochazuke`, not `app`: v0.16.0's `app.<noun>` framework names collided with the app noun's own verbs (`app.state`, an application verb, against the framework noun `app.state`).

- Framework nouns are canonical `ochazuke.<noun>` (`ochazuke.settings`, `ochazuke.list`, `ochazuke.page`, `ochazuke.state`, `ochazuke.command`, `ochazuke.grid`, `ochazuke.markdown`, …); `FrameworkNamespace` is `"ochazuke"`, and the new `AppNoun` (`"app"`) is never namespaced. Short names are unchanged aliases. The CLI nests them under `ochazuke` (`bin ochazuke settings list`, `bin ochazuke.settings list`, `bin settings list`). Exported noun constants changed value again (`cli.CommandNoun` `ochazuke.command`, `cli.GroupNoun`, `CompletionNoun`, `TreeRowNoun`, `Form*Noun`, `markdown.DocNoun`, `markdown.TaskNoun`). Code comparing with `app.<framework noun>` must compare with `ochazuke.<noun>`.
- An application verb on `app` named like a framework noun (`app.state`, `app.settings`) is accepted and stands beside it: `app.state` is the application's verb, `state.get` / `ochazuke.state.get` the framework's.
- Compatibility: the v0.16.0 spelling `app.<framework noun>` (keys, `Do`, `Request`, `bindings.json`, `actions.json`, restored `history.jsonl`, the palette, `bin app settings list`, `bin app.settings list`) is a deprecated alias of `ochazuke.<noun>` for one release, unless a noun of that exact name exists or `app` has a verb of that name; history reads it back canonical (`ochazuke.`).
- `cli.ExtensionNamespace(bin)`: the namespace every host mounts an extension under (`cli.Namespace`, `cli.Local`): the base name of the binary, lower-cased, a leading `o-` dropped (`o-ai` is `ai`, `o-qbt` is `qbt`, `o-git` is `git`, `o-csv` is `csv`; `mtm-mermaid` stays `mtm-mermaid`); an error when what is left is not one noun word or is `ochazuke`, `app` or the short name of a framework noun.
- Fix: `cli.Catalog` listed a noun more than once when its verbs sorted around the nouns nested under it (`app` three times in o-qbt's catalog); it now groups by noun, nouns by name and each noun's verbs by name.

### Card timelines

- New component `Timeline` (`timeline.go`): `Runtime.AddTimeline(id, cards, opts...)` draws a scrolling column of boxed cards of varying height (`Card`: header wrapped in full, a meta line, a body and foldable `CardSection`s shown only while open, each section in its own `CardRole` style). Cards are instances of the app's nouns (rows of a list child), so selection, j/k with counts and spills, `g g`, ctrl+d/ctrl+u and the `/` filter are the list's. Options `FollowTail()` (stick to the end: appends select the newest card, a growing last card keeps its end in view; moving or scrolling up stops it, `G` or reaching the end resumes), `HeaderLines(n)` (cap a closed header with `… N more lines`), `NoSpill()`.
- Emphasis: `Active` (bold header, `●` in the top border, readable in mono), `Muted` (older cards), `Group` (a labelled full-width rule between groups). Selection: the selected card's header reversed and its border heavy in the accent.
- Keys (rows on `ochazuke.timeline`): `enter`/`space` toggle, `l`/`h` open/close, `z o`/`z c`/`z a`, `z R`/`z M` all, `z 1`–`z 9` fold a section, `J`/`K`/`ctrl+e`/`ctrl+y` scroll line-wise, `G` the end.
- Data in: `SetCards` keeps selection, open cards and folds by id; `Patch(cards...)` updates or appends cheaply for streaming. Bodies render lazily (open and on screen), cached by id, width, `Revision` and folds; a frame costs the same at 500 and 5000 cards (`BenchmarkTimeline`).
- o-story: a page's `timeline` field (`TimelineSpec`, `CardSpec`, `SectionSpec`), stories `timeline/wrap`, `open-close`, `follow-tail`, `active-mono` at 80 and 120 columns, `timeline/open-close`, `follow-tail`, `spill-to-list`.

- The extension side caches each list's last versions (`Shell.StateCache`): `(id, record hash)` files under `$XDG_CACHE_HOME/<bin>/state/<scope>/lists/<list>/`, written temp + rename and content-addressed, `Keep` (2) versions per list and `Scopes` (8) scopes, the rest deleted. `StateCache.Scope(args)` adds to the scope (a TUIOS server); `StateCache.Fingerprint(args)` (`StatFingerprint(paths...)`) answers an unchanged poll without running the verb, except under `--fresh`; `StateCache.Off` turns it all off.
- `MountPage` uses it: with `PageConfig.FetchFlags` a page's `Reload` sends its list hashes and applies the answer (`PageView.ApplyState`): unchanged touches nothing and skips `OnRows`, a delta goes through `List.Patch`, full through `SetRows`; a list whose hash does not match after applying is fetched again in full, once. `PageView.Refresh` forgets the hashes. An older extension (no `stateDelta`) keeps full answers through `Fetch`.
- `List.Patch(ListPatch{Upsert, At, Remove})` (and `PatchItems`) is `SetItems` over the patched rows: kept rows keep their instances, selection and marks, and only removed rows close. `SetItems` keeps a table's measured widths when every row draws the same cells.
- `cli.DecodeState` and `RowReader.Answer()` read a delta answer. Benchmarks `BenchmarkStatePoll` and `BenchmarkStateApply` cover an 8,000-row poll, unchanged and with one row changed.

### Builtin verbs

- Every ochazuke tool's catalog lists the framework's verbs beside the tool's, and some are application verbs (the outline's 14, the chooser's 3), so hosts mounted them as the tool's (`ai-outline`, `qbt-outline`). `Operation.Builtin` now marks every operation the framework registers: everything `NewRuntime` and `NewModel` register, and what a framework constructor registers later (`NewPicker`, `NewPalette`, `NewAppearance`, `grid.Register`, `markdown.Register`, `cli.AddCommands`). ### Every list filters

- `/` on a focused list (page lists, tables, catalog lists, the Settings page's section, a list in a modal) opens a query line above the rows; typing keeps the rows whose label or cells hold every word, ignoring case, in list order, `N of M` on the right. ## v0.6.0 (2026-10-26)

### Highlights

- `config export [DIR]` writes a complete reference of an application's user configuration, by default into `<config dir>/reference/`: `settings.json` (every declared setting at its current value), `settings.reference.json` (type, default, enum, description and value per setting), `bindings.reference.json` (every key row, `bindings list --all`), `actions.example.json` and `themes.example.json` (every field, valid as they are) and a `README.md` explaining each file, where the live files are, and that copying defaults pins them. Files are written atomically; the live config files are never written without `--force`.
- `config path` prints the config, state and default reference directories.
- A binding row's guard is part of its identity: identity is the noun or instance, the mode, the keys or pattern, and `when`. A row with `when: X` replaces only the row with the same keys and guard `X`; a row without `when` replaces only the unguarded one; an unbind (`"request": null`) removes only the row with its own `when`. This holds for `Runtime.Bind`, the builder (`Bind`, `Pattern`, `When`, `Unbind`), `bindings.load`, the user `bindings.json` and `bindings.reload`'s undo, so a guarded row and its fallback on the same keys can be overridden or unbound one at a time, and `config export`'s `bindings.reference.json` loads back exactly. A replaced row keeps its place in the table (it used to move to the end), a new guarded row goes before the unguarded row on its keys so it answers while its guard holds, and reload puts a replaced row back where it stood. The `input` guard the framework puts on the editor's `input.*` rows (`ImplicitGuard`) is not part of the identity: a row without `when` replaces or unbinds those defaults as before, and a user row running an `input.*` operation on the editor noun gets the guard too.
- The user `bindings.json` loader reports a row that a guarded default on its keys still answers before, as a notice (`bindings.json: row N KEYS: the default NOUN.VERB row (when "G") answers first while its guard holds; to replace it, add "when": "G"`): an added row behind a guarded row, any row behind a guarded capture row on its keys (`ctrl+c` and its `no-modal` capture row), and an unbind without `when` that leaves a guarded row in place.

### API changes

- `ModeBuilder.UnbindGuarded(keysOrPattern, guard)` removes the row with that guard; `ModeBuilder.Unbind` now removes only the unguarded row. `ModeBuilder.When` after `Bind` re-places the row under its guard (an unguarded row it replaced comes back).
- `Runtime.ExportConfig(dir, force) (ConfigExport, error)`, `ConfigExport{Dir, Files, Config, State}`; `Config.Paths() ConfigPaths`, `ConfigPaths{Config, State, Reference}`.
- The `config` noun: `config.export {dir, force}` (`dir` positional), `config.path`.
- Constants `ReferenceDir`, `ReferenceReadme`, `SettingsReferenceFile`, `BindingsReferenceFile`, `ActionsExampleFile`, `ThemesExampleFile`.

### Migrating

- An unguarded row no longer replaces or unbinds a guarded row with the same keys; it adds an unguarded row beside it (which answers only where the guarded row's guard is false), and the loader says so in a notice. To replace or unbind a guarded default, give the row the default's `when` (`bindings list --all` and `bindings.reference.json` show it). The editor's implicit `input` guard is the exception: `{"noun": "editor", "mode": "normal", "keys": "x", "request": null}` still unbinds `x`. The defaults with a guard of their own are few: `0` in `operator_pending` (`when: count`), the `ctrl+c` capture row (`when: no-modal`), and the rows an application guards. ## v0.5.0 (2026-10-26)

A minor release: inline completion for inputs, a preserved-newlines option for Markdown, and `Runtime.Bind` no longer cancels a key sequence it does not touch.

### Highlights

- Inline completion: an application gives an input triggers such as `@`, `$` or `[[`, each with an asynchronous search. Typing a trigger at the start of a token offers the search's suggestions for the rest of the token in a list drawn under it, while typing keeps editing the same input.
- The token runs from the trigger to the next whitespace (`/` never splits it); the query is the whole token after the trigger, wherever the cursor is inside it. Of overlapping triggers (`[` and `[[`) the longest wins.
- Accepting replaces the whole token and keeps the trigger (`@src/ma` becomes `@src/main.go`) as one undoable edit.
- Searches run off the loop after a 150 ms pause in typing. An answer to a request older than the one on screen is dropped, so a slow, late answer never replaces a newer one; a search error is shown in the list.
- Keys while the list is open: `ctrl+n`/`ctrl+p` or `down`/`up` move, `tab` takes the highlighted suggestion (else the first), `enter` takes it only once one is highlighted (so enter after a typed token still submits or breaks the line), `esc` hides the list and stays in insert. `tab` on a token with the list closed opens it at once, unless the application binds `tab` itself.
- The demo's notes field completes `@` library entries, `$` skills and `[[` pages. o-story stories `completion/*` (typing-opens, look, accept-undo, escape-stays-insert, error-row, mid-token-tab, longest-trigger); a story input takes `completions: [{trigger, items, fail}]`.
- Markdown keeps line breaks on request: `markdown.PreserveNewlines()` makes every newline inside a paragraph a line break (Glamour's `WithPreservedNewLines`), for notes written as plain lines. Long lines still wrap; code blocks and tables draw the same. A Doc with the option keeps its items, highlight and byte-exact toggles. o-story stories `markdown/preserve-newlines` and `markdown/render-preserve-80`.
- `Runtime.Bind` and the builder's `Define(noun).Mode(m).Bind` while a key sequence is pending (`d` of `d d`) keep the sequence unless a row they add or replace is on it: in its mode, with keys equal to, extending or extended by the keys typed so far. Before, any new row cancelled it, so an application binding rows mid-sequence broke `d d`.

- `Completions(triggers...)` (an `InstanceOption` read by `AddInput`) and `NounBuilder.Completions(triggers...)`; `Input.Completions`; `Runtime.CompletionTriggers(id)` (the input's own, else its noun's). A trigger must be non-empty, hold no whitespace and have a search.

- `FindCompletionToken(text, cursor, triggers) (CompletionToken, int, bool)` and `CompletionToken{Start, End, Trigger, Query}`.
- `Runtime.Completer() *Completer`: `Open`, `Input`, `Token`, `Suggestions`, `Err`, `Highlighted`, `Searching`, `State`, `Debounce`, `DebounceTick`, `DebounceCurrent`; `CompletionDebounceMsg{Seq}`, `DefaultCompletionDebounce`, `CompletionNoun`.

- Binding rows can pass the acted-on row's data as an argument (`Binding.FromRow`, `"row:<field>"` in binding files).
- Confirm prompts for CLI calls without a target read the request's arguments instead of naming `app`.
- The `?` help is a list table (`helpColumns`: key, operation, arguments, description) instead of its own column layout: a header line, the selected row as the reverse highlight alone (no `> ` marker), section labels and wrapping from the table. Content and order are unchanged.

### API changes

- `Column.Wrap`: in `List.View` a long cell wraps onto further lines of its row instead of being cut (`TableText` still cuts). `Column.Max` caps a flexible column's growth. Both are in the catalog's `columns` (`wrap`, `max`).
- `ListItem.Section`: a table draws a label line above each run of rows in one section, repeated at the top of a window that starts inside it.
- Confirm prompts without a target instance: a request that addresses no instance of the verb's noun (a CLI call with positional words) expands `{{noun}}` to the verb's noun and `{{id}}`, `{{target}}`, `{{label}}` to the argument of that name, else its first argument in `ParameterOrder`, instead of naming `app` (o-git gap).
- `Binding.FromRow(arg, field)` (`SourceRow`; `"row:<field>"` or `"row"` in a binding file's `from`): a binding row passes the acted-on row's `Data` as an argument (a map key or struct JSON field, dotted for nested values; the whole value JSON-shaped), reading the focused row also when the row is bound on the list; a missing field leaves the argument out, and `ValidateBindings` rejects a malformed field (o-git gap).

## v0.1.1 (2026-10-25)

Requires oden v0.1.1. Fixes from mtm's test pass:

- `Tree.Record(TreeAction{ID, Label, Undo, Redo})`: an application change kept outside the nodes (a task status) goes on an outline's undo stack in order with the tree's edits. Story `tree/undo-app-action`.
- The footer shows only the newest notice, cut to half the width with `(+N more)`, so notices never hide the hints. Story `notices/footer-keeps-hints`.
- An argument error (`ArgumentError`, `Response.Argument`) adds no `pass --target, one of: …` hint in the CLI.
- `?` help: a row's `Help` replaces its operation's description (the `"`, `q`, `@` and count rows now say what they do); a generated prefix cancel (`d esc`) is listed only while a sequence on its prefix answers.

## v0.1.0 (2026-10-25)

First tagged release. Requires Go 1.26 and oden v0.1.0.

- Bubble Tea v2 application framework: retained pages, nouns and instances, one focus field and one global mode, one stack walk for actions and bindings, binding rows (`Define`, bindings files, capture rows, verb guards), `ValidateBindings`.
- Components: lists and tables (lists with columns), the tree and outline editor (`AddTree`), modal text inputs with an undo tree, registers and macros, the file picker, terminal instances, partial-screen modals and confirm prompts.
- Chrome: the ex-mode command line and palette with parameter choices, footer hints as `key noun.verb`, `?` bindings help, a notice line and the two-row jobs ticker.
- Runtime: operations with a delivery contract for off-loop jobs, action history with dot-repeat, tree queries, and live control over a Unix socket.
- `cli`: the generic NOUN VERB shell, the catalog answer and `cli.Mount` into oden command groups.
- `story` and `o-story`: stories as data played headless against the real chrome, and session recordings.
